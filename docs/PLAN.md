## 0. 한 장 요약

| 항목 | 내용 |
|---|---|
| **무엇을** | MYOMORPH-MK. 1(실제로 작동 가능한 근골격 티타늄 슈트)이 **한 사람의 몸 위에 조립되는 과정**을 보여 주는 스크롤형 인터랙티브 웹 경험 |
| **한 줄 메시지** | **"NOT ARMOR. ANATOMY."** 몸 위에 짓는 두 번째 몸 |
| **서사 (v2.0)** | 어둠 속 조립 셀 → 전원 → **레이싱 슈트형 신경 언더슈트와 바라클라바를 입은 도하** → 도하의 레퍼런스 도면 → 몸 측정 → 신경 인터페이스 → 천장의 로봇팔 4대가 **몸 바깥에** 부츠, 골격, 근육, 시스템, 판, 헬멧 순으로 조립 → 탯줄 분리와 함께 **완성된 슈트 첫 공개** → 움직임 → 기능 → 부품 5,819개 놀링 → 자유 탐색 |
| **분량** | 프롤로그 + 16개 챕터, 기준 감상 속도로 **약 290초**(시스템 카드를 접으면 약 220초) |
| **디자인 원천 (v3.0)** | **슈트 외형 전체 = 도하의 새 레퍼런스.** 헬멧과 얼굴(PERSONA)도 도하가 그린다. 나는 모든 선을 읽어 판 하나하나를 독립된 3D 판으로 만들고, 비율만 도하 몸에 맞게 조금 조정해 보고한다. '근육처럼 보이게' 같은 해석은 더하지 않는다. 근육 해부학은 센서 위치(SENIAM), 제어 모델(근육 표), CORPUS 서사에만 쓴다 |
| **밀도** | 부품 5,819개(체결구 2,826 포함), 사전 조립 모듈 41개, 판 477장, 시스템 13개. **판에 따라 바뀌는 수치는 이전 청사진 기준 잠정치**이고 새 레퍼런스로 다시 계산한다. 모든 수치는 `engineering/bom.json` |
| **공학 요약** | 슈트 36.6 kg(잠정, 사람이 입는 것은 1.92 kg) · EHA 근육 6개(무릎 64 N·m) · 배터리 = 등판 2장(0.84 kWh, 약 3.7시간) · 막 아가미 냉각(압축기 없음) · 근전도 784 ch + 뇌파 32 ch(지연 43 ms) |
| **렌더링** | **하이브리드**(도하 결정 2026-10-03): 조립 장면은 경로추적으로 미리 렌더해 스크롤로 재생하고, 그 위에 실시간 레이어(호버, 콜아웃, 신호)를 얹는다. 시스템 카드, 움직임, 놀링, 자유 탐색은 three.js 실시간 |
| **기술** | Blender 5.2.1(bpy, 파이프라인 전체를 코드로) → Cycles 프레임 시퀀스 + glTF(meshopt) → three.js WebGPU(WebGL2 폴백) + Web Audio(물리 모델링 합성) → **Vite 빌드 → 여러 파일짜리 Artifact로 발행** |
| **색** | Blender AgX를 3D LUT로 구워 실시간 레이어에도 같은 변환을 적용(ΔE로 검증) |
| **진행** | 8단계(P0~P7), 승인 게이트 8개(G0~G7). P0 완료, P1 R1·R2 완료. **P1 R3: 레퍼런스 인수 준비 완료 → 레퍼런스가 오면 INTAKE 절차 → G1** |

## 1. 브리프 해석: 지킬 것, 바꿀 것, 더할 것

### 1.1 그대로 지키는 것 (도하 의도의 핵심)

- **슈트 외형은 도하의 새 레퍼런스 그대로**(2026-10-03 v3.0 결정).
  - 모든 선을 분석해 판 하나하나를 레퍼런스에 그려진 그대로 만든다. "근육처럼 보여야 한다" 같은 해석은 더하지 않는다.
  - 레퍼런스 비율이 도하의 몸과 완벽히 맞지 않으면 비율만 조금 조정하고, 조정한 곳을 % 단위로 보고한다.
  - 헬멧과 얼굴(PERSONA)도 도하가 디자인한다. 나는 기능 요구(§5.7)만 맞춘다.
- **슬림하게, 장치는 실루엣 안에**(2026-10-03 결정). 장치가 레퍼런스 외형 안에 들어가지 않으면 먼저 내부 배치를 바꾸고, 그다음 성능을 줄이며, 외형을 바꿔야 할 때만 도하에게 묻는다(§5.13).
- **모든 기계는 몸 바깥에 있다**(2026-10-03 결정).
  - 동력, 구동, 냉각, 생명유지, 센서는 로봇팔이 사람 바깥에 조립한다.
  - 외부 패널이 그것을 덮거나, 패널 자체가 기계의 일부가 된다(배터리 = 등판).
- **사람이 먼저, 완성은 끝에.**
  - 레이싱 슈트형 언더슈트와 바라클라바를 입고 사람처럼 움직이는 도하가 먼저 나온다.
  - 천장의 로봇팔이 부품을 조립해 완성한다.
  - 완성된 전신은 11 RELEASE에서 처음 보여 준다.
- **외부 케이블은 불가피할 때만 쓴다**: 충전, 덥고 습한 날의 냉각 라인, 셀 안에서의 기동과 진단(§5.12).
- 분절 금속 패널이 전신을 덮는다(브리프). 판 나눔은 레퍼런스가 정한다. 브리프 규칙(통짜 흉갑 없음, 관절을 가로지르는 강체판 없음)과 레퍼런스가 부딪히면 도하에게 묻는다.
- 패널은 껍데기에서 끝나지 않는다: 보호, 수납, 냉각(루버), 모듈 교체, 상태 표시, **에너지 저장(배터리 패널)**.
- 관절을 가로지르는 강체판 없음. 판은 겹치고 미끄러지며, 일부 판은 따로 움직인다(루버, 툴 베이, 배터리 이탈 등. 어느 판이 움직이는지는 레퍼런스의 판 목록과 도하의 메모로 정한다).
- 목과 허리는 분절형 **수동** 구조다. 허리는 티타늄 판스프링 척추로 굽힐 때 에너지를 저장한다.
- 기능 5종:
  1. 전완 툴 베이
  2. 교체형 패널(배터리 패널, 교체 포트)
  3. **아래쪽으로 열리는** 냉각 루버(갈비뼈 모양 금지). 위치는 레퍼런스에 그려진 통풍구를 따른다
  4. 보조 손
  5. 근섬유 방향 상태 표시(색 + 패턴)
- 착용자(도하): 178 cm / 윙스팬 182 cm / 65 kg / 체지방 10 % / 20대 초반. 분석 결과 허리 71 cm, 삼각근 너비 47 cm, 가슴 93 cm([`research/wearer-anatomy.md`](research/wearer-anatomy.md)).
- 공학 고증 최대. 단 하나의 예외는 **배터리 셀 에너지 밀도를 2036년 수준으로 가정**하는 것(도하 지정).
- 금속은 티타늄과 골드티타늄(TiN). **무광, 가볍게 쓴 흔적**(2026-10-03).
- three.js와 Blender 모두 사용. Vite 빌드. AgX. 풍부한 사운드. 모든 UI에 모션. 커서와 스크롤 상호작용.

### 1.3 내가 더하는 것 (새 아이디어)

| 코드 | 아이디어 | 한 줄 설명 |
|---|---|---|
| **A′** | **몸 바깥의 두 번째 해부학** (v1의 A 대체) | 층 순서가 인체를 닮았다: 피부 → 신경 언더슈트(근막) → 커프 → 프레임(뼈) → EHA(근육)와 힘줄 → 배터리·아가미·연산부(장기) → 판(근육의 외형). 기계는 사람 근육 **안**이 아니라 사람 **바깥**에서 같은 일을 한다 |
| **B** | **키네틱 벌지** | EHA가 늘어나면 덮는 판이 살짝 부푼다 |
| **C** | **결 방향 이방성 금속** | 헤어라인 결 = 판의 장축(레퍼런스에 결 표시가 있으면 그 방향) |

## 2. 레퍼런스 기반 디자인 (v3.0)

> **도하 결정 (2026-10-03)**: 마네킹 기반 슈트 디자인을 폐기한다. 도하가 팔 안쪽, 다리 안쪽까지 모든 면이 들어간 자세한 레퍼런스를 보낸다. 나는 모든 선을 정확히 분석하고 판마다 3D 형태를 생각하며 **그대로** 만든다.

### 2.1 왜 바꾸나: 이전 방식의 실패

이전 슈트는 정면 청사진의 2D 선을 **마네킹 피부를 부풀린 한 장의 껍데기**에 투영해서 만들었다.

| 증상 | 원인 | 이번 대책 |
|---|---|---|
| 해칭과 두 줄 선이 전부 이음선이 됨 | 선의 의미(판 경계, 꺾임, 음영)가 구분되지 않은 래스터 한 장 | 의미별 색·레이어 규칙(GUIDE §5) |
| 경계가 계단 모양, 이음선이 점선처럼 끊김 | 래스터 경계 + 메시 간격(약 4 mm)보다 좁은 홈 | 벡터 레퍼런스. 판은 홈이 아니라 따로 만든 솔리드 |
| 판이 독립 조각이 아님 | 한 장의 껍데기에 홈을 낸 것 | 판마다 닫힌 윤곽 → 독립 솔리드(두께, 헴, 모따기, 틈, 겹침) |
| 옆면, 안쪽, 뒷면을 추측으로 채움 | 정면 한 장 + 측면 한 장뿐 | 모든 면이 보이는 뷰 세트(GUIDE §4) |
| 헬멧이 덩어리처럼 뭉개짐 | 정면·측면 윤곽만으로 로프트 | 헬멧 4면과 얼굴을 도하가 그림 |
| 선 굵기가 들쭉날쭉해 금이 간 것처럼 보임 | 손그림 획 굵기를 그대로 홈 너비로 씀 | 홈 너비는 공학 규칙(§5.3)으로 정하고, 선은 위치만 쓴다 |

### 2.2 새 원칙

1. **레퍼런스 = 설계도.** 선의 뜻은 가이드 규칙을 따른다: 검정 굵은 선 = 판과 판 사이 틈, 파랑 가는 선 = 한 판 안의 꺾임, 빨강 점선 = 가려진 선과 겹침, 초록 = 나사·통풍구·조명·디스크.
2. **판은 독립 솔리드다.** 한 장의 껍데기에 홈을 내지 않는다. 판마다 곡면, 두께, 헴, 모따기, 틈, 겹침 순서를 가진다.
3. **해석하지 않는다.** 근육 모티프나 내 취향을 더하지 않는다. 레퍼런스에 없는 면은 질문 목록으로 도하에게 묻고, 답이 오기 전에 임시로 채운 곳은 표시해 둔다.
4. **비율 조정은 작게 하고 보고한다.** 높이 기준선(정수리, 어깨, 허리, 가랑이, 무릎, 발바닥)에 맞춰 구간별로 늘이거나 줄이고 % 표로 보고한다. 5 %를 넘는 조정은 도하에게 먼저 확인한다.
5. **도하 몸 모델은 확인용이다.** 판이 피부 + 12 mm 바깥에 있는지, 장치 깊이(§5.13), 가동 범위 간섭(§5.10)을 검사하는 데만 쓴다. 형상을 만들지 않는다.

### 2.5 이전 레퍼런스에서 남기는 사실 (참고)

이전 정면 청사진과 측면 평면도는 [`reference/previous/`](reference/previous/)에 기록으로만 둔다. 새 레퍼런스에 비슷한 요소가 있을 때 다음 사실을 참고한다.
- 측면 평면도는 1.265 mm/px(그림 높이 1,452 px = 1.837 m)로 읽혔다. 가슴은 피부 바깥 40~60 mm, 등 위쪽은 40~74 mm로 그려져 장치 깊이가 넉넉했다.
- 몸과 부딪힌 곳은 세 군데였다: 엉덩이판 위 허리 뒤(여유 0.5~10 mm), 무릎 뒤(−8~3 mm), 발끝(14 mm 튀어나옴). 새 레퍼런스에서도 이 세 곳을 먼저 본다.
- 관절 디스크를 기능에 연결하는 안: 무릎 = 교차 4절 링크 커버, 팔꿈치 = 힘줄 구동 캡스턴(모터는 위팔 뒤), 발목 = 부츠 힌지, 손목 = 수동 베어링 링. 어깨 위 큰 판 아래에는 어깨 스프링과 견갑 레일, 옆구리 루버 뒤에는 아가미, 등의 솟은 부분에는 배터리 등판과 척추 연산부가 들어간다.

**MYOMORPH = myo(근육) + morph(형태)**. "근육의 형태를 가진 기계."

### 3.2 '근골격 슈트'의 공식 정의 (R2: 몸 바깥의 층 구조)

외골격(갑각)은 단단한 껍데기가 몸을 가둔다. **MYOMORPH의 근골격 구조**는 사람 몸 **바깥에** 인체처럼 층을 쌓는다.

- 힘은 **EHA와 힘줄(근육과 힘줄)**이 만든다.
- 동작의 자유는 몸에 닿지 않고 떠 있는 **레퍼런스의 판(외형)**이 만든다.
- 사람과 닿는 곳은 언더슈트와 커프 10개뿐이다.

### 5.3 패널 규칙 (v3.0: 레퍼런스 우선)

**분할의 원천**
1. **이음선 = 레퍼런스의 검정 선(판 틈).** 파랑 선은 한 판 안의 꺾임이고, 빨강 점선은 다른 판 아래로 들어간 가장자리다(GUIDE §5).
2. 판 수는 레퍼런스에서 센다. 이전 청사진의 477장(정면 208, 후면 102, 사지 후면 44, 헬멧 40, 손 38, 루버·라멜라 45)은 계산서의 잠정 입력으로만 남아 있다.
3. 레퍼런스에 없는 면은 도하에게 묻는다. 답을 받기 전 임시로 채운 판에는 `provisional` 표시를 달고 확정 판과 섞지 않는다.

**판 만들기** (새 방식, 상세는 INTAKE 4~5단계)
1. 판마다 닫힌 윤곽을 뷰별로 뽑아 같은 판끼리 짝짓는다(높이 기준선과 판 ID로).
2. 정면·측면·후면 윤곽과 단면(있으면)에서 판의 바깥 곡면을 만든다. 마네킹 표면에 홈을 내지 않는다.
3. 두께, 헴, 모따기, 틈 인셋을 넣고, 빨강 점선으로 겹침 순서를 정한다.
4. 판 ID, 역할 태그, 체결점, 재질을 붙인다.

**역할 태그** (모든 판에 1개 이상)

| 태그 | 의미 | 예시 |
|---|---|---|
| D | 조형 | 대부분 |
| P | 보호 | 무릎, 정강이, 전완 |
| F | 구조 | EHA 클레비스 위 판 |
| M | 기능 모듈 | 배터리 등판, 툴 베이, 교체 포트 |
| S | 슬라이딩 | 관절 주변의 겹침 판 |
| V | 냉각 루버 | 레퍼런스의 통풍구 |
| L | 상태광 | 이음선 속 라이트파이프 |

**공학 규칙**
1. 루버와 라이트파이프는 판 안에 숨긴다. 레퍼런스의 통풍구가 그대로 루버가 된다.
2. 헤어라인 결 방향 = 판의 장축(레퍼런스에 결 표시가 있으면 그 방향).
3. 관절을 가로지르는 단일 강체판 금지(자동 검사). 레퍼런스에 그런 판이 있으면 나눌 곳을 도하에게 묻는다.
4. 겹침은 지붕 기와 원칙(위 판이 아래 판을 덮는다). 레퍼런스의 빨강 점선이 우선한다.
5. 간격: 일반 1.5 mm(±0.2), 슬라이딩 2.5 mm, 루버 개방 시 최대 8 mm. 손그림 선 굵기는 틈 너비로 쓰지 않는다.
6. **두께 0.6 mm**(잠정). 강성은 헴과 프레스 비드로 낸다. 판은 구조가 아니라 외피이고, 하중은 프레임이 받는다. 레퍼런스에서 판 가장자리가 두껍게 보이면 헴과 플랜지로 그 두께를 낸다.
7. 가장자리: 0.4 mm 챔퍼, 안쪽 헴 2~4 mm.
8. 고정: 탄소 캐리어(36개) 위 방진 그로밋, Ti M2.5 0.45 N·m. 교체 판(배터리, 포트, 툴 베이)은 쿼터턴.

### 5.4 구동 배치 (R2: 슬림 제약 아래, 보조 25 %)

**원칙**
- 슈트는 **자기 무게를 100 % 스스로 지고**, 착용자의 관절 피크 모멘트에 **25 %를 보탠다**(v1 40 %).
- 피크 모멘트는 사람의 일상 최대 작업(계단, 일어서기, 밀기) 기준 N·m/kg이다.

- **슈트 질량이 커지면 근육이 커지고 근육이 커지면 질량이 커지므로, 둘을 고정점이 될 때까지 반복 계산했다.**
- (v3.0) 질량이 판 수와 판 면적에 따라 바뀌므로 아래 표는 잠정이다. 레퍼런스 판 목록으로 고정점을 다시 구한다.

**EHA를 고른 이유**
- 중앙 유압 펌프(HPU)와 긴 고압 배관을 없앤다.

  - 배관은 누유 위험이 있고 모듈 교체를 막는다.
- 펌프 제어(밸브로 압력을 버리지 않음)라 효율이 0.38 → 0.55로 오른다.
- 자유 스윙 바이패스: 다리를 흔드는 구간은 저항 없이 따라오고, 고장 시 기본으로 열려 사람을 가두지 않는다.

### 5.10 공학 검증 방법
- **공간 검사**: 모든 장치 두께 ≤ 그 자리의 (피부 → 판 바깥면 거리 − 언더슈트 3.5 − 틈 2.0 − 그로밋 2.5 − 판 0.6). v3.0에서는 레퍼런스 판 모델로 다시 잰다(§5.13, INTAKE 6단계).
- **레퍼런스 충실도(v3.0)**: 판 모델을 레퍼런스와 같은 정사영으로 렌더해, 판 경계와 레퍼런스 검정 선 사이 거리(mm)를 잰다. 비율 조정분은 되돌려 비교한다(§12.1).
- **간섭 검사**: ROM 포즈 약 40개에서 판끼리, 판과 모듈, 모듈과 착용자 BVH 교차 0건(P2).
- **질량 특성**: 부품별 체적 × 밀도 → 총질량, 무게중심, 좌우 균형.
- **기구학**: EHA 길이와 관절각, 4절 링크 ICR, 힘줄 길이 변화. 런타임과 같은 코드.
- **수치 일관성**: 사이트의 모든 수치 = JSON, 빌드 시 대조.

### 5.11 신경 인터페이스와 제어 (R2 신규)

**'뇌와 연결'의 공학적 답: 두 번 읽는다.**

| 층 | 무엇을 읽나 | 센서 | 언제 | 맡는 일 |
|---|---|---|---|---|
| 뇌 | 운동 준비 전위(MRCP), 뮤·베타 리듬 감소(ERD), **오류 관련 전위(ErrP)** | 바라클라바 건식 전극 32(10-10, 운동피질 촘촘), 헬멧 라이너가 누름 | 움직이기 0.5~1.5 s 전 / 잘못된 움직임 직후 | 동작 모드 선택(걷기, 계단, 들기, 공구), 시작 허가, **오류 시 즉시 정지와 적응** |
| 척수 | 운동단위 발화(근전도를 운동신경 하나하나의 명령으로 분해) | 고밀도 격자 24 × 32 ch + 양극 16 = 784 ch | 힘이 나기 30~100 ms 전 | **연속 토크 제어**: 신경 구동 → 근골격 모델 → 관절 토크 |
| 몸 | 자세, 보행 단계, 하중 | IMU 17, 엔코더, 하중 센서 8, 압력 깔창 32구역 | 실시간 | 상태 추정, 안전 한계 |

- **제어 법칙**: τ_suit = 0.25 × τ_bio,est + τ_self.
  - τ_bio,est는 근전도로 구동하는 Hill형 근육 모델에서 나온다. 파라미터는 **도하의 근육 표**(`muscles.json`: 최대 힘, 최적 섬유 길이, 깃각)다.
  - τ_self는 슈트 자중 보상이다.
- **안전**:
  - 관절별 토크와 속도 한계, 하드 스톱
  - 오류 전위 거부권, 락스텝 안전 MCU
  - 고장 시 EHA 바이패스 개방(자유 스윙), 기계식 비상 해제
- **왜 침습형이 아닌가**: 근전도는 이미 척수 운동신경의 명령 그 자체를 피부에서 읽는다. 뇌 임플란트 없이 같은 정보를 얻는다.

### 5.13 공간 요구 (v3.0: 장치가 판 아래에 들어가려면)

R2 셸의 공간 분석 결과(부위별 거리 지도, 53/53 통과 표)는 셸과 함께 폐기했다. 남는 것은 **장치의 두께**와 **층의 두께**다. 둘을 더한 **필요 깊이**를 템플릿과 가이드(GUIDE §8)에 넣어, 도하가 그릴 때부터 디자인과 공학이 맞도록 했다.

**층 두께**: 언더슈트 3.5 + 틈 2.0 + 그로밋 2.5 + 판 0.6 = **8.6 mm**. 템플릿의 판 바깥면 최소선은 피부 + 12 mm다.

**필요 깊이 = 장치 두께 + 8.6 mm** (피부 → 판 바깥면)

| 위치 | 장치 (두께) | 필요 깊이 |
|---|---|---:|
| 등 상부 | 척추 연산부 18 mm(가운데), 배터리 등판 9 mm(양옆) | ≥ 27 mm |
| 허리 뒤 | 배전 22, 교체 버퍼 18, 펌프·매니폴드 15 mm | ≥ 31 mm |
| 엉덩이 뒤 | 고관절 EHA 18 mm | ≥ 27 mm |
| 허벅지 앞 | 무릎 EHA 20 mm | ≥ 29 mm |
| 종아리 뒤 | 발목 EHA 18 mm | ≥ 27 mm |
| 무릎 바깥 | 교차 4절 링크 판 6 mm | ≥ 15 mm |
| 고관절 옆 | 고관절 3축 조인트 26 mm | ≥ 35 mm |
| 옆구리 | 루버 팬 14 mm, 막 아가미 12 mm | ≥ 23 mm |
| 가슴 | 비상 해제 손잡이 12 mm | ≥ 21 mm |

|---|---:|---|---:|

**검사** (레퍼런스 모델에서 다시 한다)
1. 판 모델의 안쪽 면에서 피부까지 거리를 잰다.
2. 장치를 몸 랜드마크에 붙이고, 각 장치 발자국 안의 하위 10 % 거리를 가용 두께로 본다.
3. 장치 두께가 가용 두께보다 크면 실패다. 대응 순서: 내부 배치 변경 → 장치 재설계(더 얇게) → 성능 조정 → 외형 변경 문의(도하).
4. 검사기는 새로 만든다(MYOFORGE B16). 이전 `clearance.py`, `modules.py`는 R2 셸 전용이라 함께 폐기했다.

R2에서 검사를 통과시키며 배운 것: 정면에서 보이지 않는 깊이(대퇴 앞, 위팔 뒤, 전완 손바닥 쪽)를 늘리는 것이 가장 쉽다. 무릎 링크(6 mm), 연산부(18 mm), 힘줄 구동기(14 mm), 아가미(12 mm)는 이미 얇게 재설계해 두었다.

## 6. 실사화 전략: '그림티'를 지우는 법

'그림티'는 하나의 원인이 아니라 **여러 층의 작은 거짓말이 쌓인 결과**다. 층마다 막는다.

### 6.1 형상
- [ ] 실제 스케일(m)과 실제 두께. 떠 있는 부품이 없다.
- [ ] **날카로운 모서리 금지.** 모든 모서리에 0.3~0.5 mm 베벨을 두어 하이라이트 선을 잡는다(하드서피스 실사의 1번 원칙).
- [ ] 판금의 논리: 헴, 플랜지, 비드, 드래프트, 체결부, 아이솔레이터.
- [ ] 제조 공차: 간격 ±0.2 mm, 체결부품 회전각 무작위, 패널별 미세한 높이 차.
- [ ] 패널 안쪽 면도 모델링(SPIF 자국, 리브, 클립).

### 6.2 재질
- [ ] **측정 기반 PBR 값.** G0에서 n,k 분광 계산으로 확보(선형 sRGB): 티타늄 F0 기준선 (0.441, 0.400, 0.361) [Palm, physicallybased DB와 일치], 상한 (0.619, 0.579, 0.543) [J&C], **TiN (0.614, 0.462, 0.233)** [Pflüger]. 티타늄은 데이터셋 간 20~40% 차이 → P1 비교 렌더로 확정 (조사 보고서 §10).
- [ ] **(R2) 무광**: 비드블라스트 거칠기 0.54(헤어라인 0.44, TiN 0.54), 헴은 연마로 0.3 근처. 크롬처럼 보이는 저거칠기 대면적 금지.
- [ ] **결 방향 이방성**(원칙 C): UV의 U축 = 판의 장축(또는 레퍼런스의 결 표시) → 탄젠트가 결을 따름 → `anisotropy`.
- [ ] **(R2) 사용 흔적**: 헴 연마, 이음선 옆 먼지, 드문 긁힘, 손자국, 골드 코팅 마모(BIBLES A2). 가볍게 쓴 장비. 녹, 찌그러짐 금지.
- [ ] 패널별 미세 편차: 로트 차이로 생기는 색상과 거칠기 ±2%(시드 기반).
- [ ] **스페큘러 앨리어싱 억제**(기하 스페큘러 AA): 고주파 노멀맵의 반짝거림은 CG의 대표적인 티다.

### 6.3 빛
- [ ] **Blender에서 직접 만든 스튜디오 HDRI**(스트립 소프트박스, 블랙 플래그)를 Blender와 three.js 양쪽에서 공용으로 사용 → 조명이 동일.
- [ ] 실시간 RectAreaLight로 스크롤에 따라 하이라이트가 패널을 **훑고 지나가는** 제품 공개 기법.
- [ ] 패널 간격의 접촉 그림자: 베이크 AO + 실시간 GTAO.
- [ ] 패널끼리의 상호 반사: SSR.
- [ ] 부드러운 그림자(PCSS 계열), 바닥 접지 그림자.
- [ ] **(교훈) 과노출 금지**: 1.1 m 거리 면광원 합계 약 78 W에서 새틴 티타늄이 하얀 석고처럼 보였다. 같은 거리에서 약 9~13 W가 맞았다. 어두운 바닥의 4 % 반사는 Specular IOR Level 약 0.08로 낮춘다.

- [ ] 실제 렌즈 파라미터(초점거리, 센서, 조리개) → 매크로에서 **물리적으로 맞는 피사계 심도**. 매크로 심도는 '크기의 실감'을 준다.

- [ ] 모션 블러(속도 기반): 빠르게 날아드는 부품.
- [ ] 미세한 색수차, 비네팅, 노출 연동 필름 그레인.
- [ ] 블룸은 에너지 보존형으로 아주 약하게, 상태광에만 선택적으로.
- [ ] **AgX LUT**(§8.6). 과채도 금지.

### 6.5 모션

- [ ] 접근 → 정렬(가이드 핀 미세 회전 보정) → 접촉 → 오버트래블 → 래치. 실제 조립 동작 그대로(§9.3).

### 6.6 맥락
- [ ] 부품번호, 각인, QC 마크, ISO 도면 문법 → '실제로 제작된 물건'이라는 맥락.
- [ ] 제품 사진의 구도와 조명 언어.

### 6.7 사람, 천, 로봇 (R2)
- [ ] **사람**: 모션 캡처 기반, 호흡 0.25 Hz, 체중 이동, 협조 동작. 얼굴은 바라클라바로 가려서 언캐니 위험을 낮춘다.

## 7. Blender 파이프라인

### 7.1 G0: 블렌더 방법론 심층 조사 (깊이 10/10, 브리프 필수 요구)

**원칙**: 이 조사를 끝내고 도하에게 보고해서 승인받기 전에는 블렌더 모델링, 렌더 작업을 시작하지 않는다(bpy 설치와 동작 확인까지만 한다).

> ✅ **완료 (2026-10-01)**: 보고서 [`research/blender-methodology.md`](research/blender-methodology.md), 규약 [`research/MBS.md`](research/MBS.md), 재현 스크립트 [`research/scripts/`](research/scripts/README.md). 도하 승인 대기.

**조사 범위**
1. **하드서피스 모델링 방법론 비교**: SubD + 서포트 루프 / 베벨 + 가중 노멀(게임 업계식) / 불리언 + 비파괴 스택(HardOps, BoxCutter 계열) / Mesh-to-SubD. 각각의 실제 사용처와 웹 실시간 적합성.
2. **유기적 형상 위의 하드서피스**: 조각된 근육 베이스에서 패널을 추출하는 워크플로우(패널 루프, 리토폴로지 후 분리, 쉬링크랩 + 솔리디파이), 필드 정렬 쿼드 리메싱(QuadriFlow, Instant Meshes).
3. **토폴로지와 스케일 표준**: 단위, 트랜스폼 적용, 법선, n-gon 정책, 폴리곤 예산.
4. **비파괴 워크플로우**: 모디파이어 스택 순서 규칙, 지오메트리 노드 절차적 디테일(체결부품 산포, 루버, 케이블/호스 라우팅).
5. **UV와 텍셀 밀도**: 일관된 텍셀 밀도, 트림 시트, 데칼, UDIM vs 아틀라스(웹 기준).
6. **베이킹**: 케이지, 레이 거리, 하이 → 로우, Cycles 베이크 설정, AO, 곡률, 두께, ID, glTF ORM 패킹.
7. **PBR 재질 표준**: 메탈/러프 워크플로우, 측정값 DB, 이방성, 블렌더 노드 → glTF 변환의 한계.
8. **색 관리**: AgX의 역사(Filmic → AgX), OCIO, 뷰 트랜스폼과 룩, 작업 색공간, 웹으로 가져가는 법.
9. **조명**: 제품 시각화 조명법, HDRI 제작, 실제 광량 단위.
10. **Cycles vs EEVEE**: 레퍼런스용과 베이크용 설정, 노이즈 제거(OIDN), 컨테이너 CPU 환경 최적화.
11. **glTF 익스포트 모범 사례**: 모디파이어 적용, 탄젠트, 커스텀 속성(extras), 애니메이션과 인스턴싱, 압축은 후처리로(gltf-transform).
12. **파이프라인 자동화**: bpy 헤드리스, CLI, 결정론적 빌드, .blend 버전 관리 전략, 명명 규칙, 컬렉션 계층.
13. **리깅**: 강체 부품의 본 페어런팅, 분수 회전 분배(라멜), 드라이버, IK, 기구학 제약.
14. **실시간용 최적화**: LOD, 디시메이션, 인스턴싱, 드로우콜.
15. **실사화 체크리스트**: 업계에서 널리 알려진 '렌더가 가짜처럼 보이는 이유' 계열의 원칙들(베벨, 스케일, 조명, 재질, 불완전함).
16. **업계 사례**: Blender Studio의 파이프라인 문서와 오픈 프로젝트, 하드서피스와 제품 시각화 전문가들의 공개 워크플로우, Polycount 위키(베이킹, 가중 노멀), Khronos glTF 문서, three.js 커뮤니티 모범 사례.

**방법**: 공식 문서와 1차 출처 우선. 주장마다 출처를 달고 신뢰도를 표기한다. 상충하는 관행은 비교표로 정리하고, 우리 프로젝트(웹 실시간, 헤드리스 자동화, 약 4,000개 부품)에 맞는 선택을 근거와 함께 제시한다.

**산출물**
- `docs/research/blender-methodology.md`: 조사 보고서
- `docs/research/MBS.md`: **MYOMORPH Blender Standard** 규약집(명명, 단위, 토폴로지, 모디파이어 순서, UV/베이크/익스포트 설정, QA 체크리스트)
- `myoforge/lint/`: MBS 자동 검사기 (P2부터 모든 산출물에 적용)
- 도하에게 보내는 요약 보고 (필요하면 읽기 쉬운 웹 페이지로도)

### 7.4 파라메트릭 부품 라이브러리 (밀도의 원천)

실제 규격 치수로 만든 부품 약 40~60종을 지오메트리 노드/파이썬 함수로 만들어 수천 번 인스턴싱한다.

- 체결: ISO 10642 접시머리(M2/M2.5/M3), ISO 7380 버튼헤드, 쿼터턴 패스너, 블라인드 리벳, 다웰 핀, 와셔
- 회전: 박형 깊은 홈 베어링(68xx), 크로스 롤러 베어링, 풀리, 캡스턴 드럼

### 8.1 플레이트 (L1) 규격
- **렌더**:
  - Cycles, 1600 × 900(데스크톱), 64~128 spp + OIDN 디노이즈, AgX.
  - 패스: beauty, **vector**(모션 벡터), **object index**(부품 ID), depth.
- **프레임 밀도**: 스크롤 1초당 키프레임 12장.
- **보간**: Cycles 모션 벡터로 사이 프레임을 오프라인 합성해 24장/초로 인코딩한다(강체 부품이 대부분이라 벡터 보간이 정확하다). 브라우저는 스크롤 속도에 따라 프레임을 고르고, 60 fps 화면에서는 인접 두 프레임을 교차 페이드한다.
- **인코딩**:
  - 우선 AV1, 폴백 H.264.
  - GOP 짧게(12), 청크당 14 MB 이하(Artifact 파일 한도 15 MB).
  - **WebCodecs `VideoDecoder`**로 임의 접근 디코딩 → WebGL 텍스처. 폴백은 `<video>` 시킹, 최후는 WebP 시퀀스.
- **모바일**: 960 × 540 별도 청크, 하드웨어 디코딩. 실시간 레이어만 GPU를 쓰므로 30 fps 유지가 쉽다.

### 8.2 실시간 레이어 (L2)
- **카메라 동기**: Blender가 프레임마다 카메라 행렬, 렌즈, 클리핑을 JSON으로 내보낸다. three.js 카메라가 같은 값을 쓴다. 리더선의 3D 앵커(모듈 중심, 판 중심)도 프레임마다 내보낸다(움직이는 부품 추적).
- **호버 = 부품 ID 버퍼**:
  - 프레임마다 저해상도(480p) object index 영상. 챕터마다 화면에 보이는 부품은 255개 이하다.
  - 팔레트 → 부품 번호 → `bom.json` 행.
  - 커서 아래 ID로 이름표를 띄우고, 같은 ID 영역의 윤곽을 그린다.
- **손전등(L1′)**: 디퍼드 셰이딩. GGX + 스폿 원뿔 + 거리 감쇠 + 노출. 그림자는 깊이 버퍼에서 스크린 공간으로 추적한다.
- **신호**: 근전도 파형, 운동단위 래스터, 뇌파 지도는 `undersuit.json`의 실제 전극 위치에 붙인다.

### 8.3 실시간 장면 (L3)
- **렌더러**: `WebGPURenderer` + TSL(WebGL2 자동 폴백, P0 검증).
- **씬**:
  - BatchedMesh(재질별)
  - InstancedMesh(체결구, 놀링 5,800여 개)
  - 챕터 단위 glTF 청크(meshopt)
- **재질**: §8.4 표. **플레이트와 같은 재질 값**(BIBLES A2)을 쓴다. 사용 흔적 레이어는 베이크(곡률, AO, 이음선 거리)로 옮긴다.
- **조명**: 셀을 Blender에서 등장방형 HDR로 구워 PMREM으로 쓴다. 키, 림 RectAreaLight.

### 8.6 색 파이프라인 일치 (AgX)

## 9. 인터랙션과 손맛

### 9.1 커서

1. **점검 조명**: 커서 레이가 닿은 표면을 향하는 가상 조명. 하이라이트가 이방성 결을 따라 미끄러진다. 재질의 진짜 정체가 드러나는 순간.
2. **시선 추적**: 헬멧이 커서를 따라 돈다(목 회전 ±70° 안에서, 감쇠 스프링). 목 판(레퍼런스의 목 구조)이 회전을 나눠 받으며 실제로 미끄러진다.
3. **근접 긴장**: 커서 근처 패널이 0.5~1 mm 긴장하고 상태광이 밝아진다. 미세한 서보 틱.
4. **정밀 레티클 커서**: 크로스헤어 + 슈트 표면 좌표(mm) 표시. 부품에 **자석처럼 스냅**하고 리더선 콜아웃이 그려진다. 커서 자체에 미세한 질량(스프링 추종)이 있다.
5. **길게 누르기**: 근육 수축(키네틱 벌지), 루버 개방.
6. **드래그**: 오비트(관성 + 15° 간격 디텐트 클릭), 사지 조작(IK + 관절 제한).

### 9.2 스크롤

- **Lenis**(부드러운 가상 스크롤) + **GSAP ScrollTrigger**(챕터 타임라인). GSAP는 2025년부터 플러그인까지 전부 무료.
- **마스터 타임라인**: 스크롤 진행도 p → 모든 3D 상태 = 순수 함수 f(p). 누적 상태가 없으니 **역방향 스크롤 시 완전히 분해**된다.
- **이벤트 교차 감지**: 프레임 사이에 체결 임계값을 지나면 방향별 사운드(체결음 / 해제음)를 트리거.
- **스크롤 디텐트(실험)**: 체결 임계값 근처에서 스크롤 이득이 약 100 ms 동안 60%로 떨어진다. 기계식 휠의 '노치'처럼 느껴진다. A/B 테스트 후 강도를 정하고, reduced-motion에서는 끈다.
- **속도 반응**: 스크롤 속도 → 모션 블러 강도, 서보음 피치, 사운드 모드 전환(§10).
- **챕터 눈금자**: 화면 가장자리의 측정 눈금자 = 진행도. 클릭하면 점프(빨리감기 래칫음).

### 9.3 체결 순간(Lock Moment)의 해부

### 9.4 의사 햅틱 (Pseudo-haptics)

시스템 커서를 숨기고 가상 커서를 그리면 **C/D 비율**(마우스 이동 대비 커서 이동)을 조작할 수 있다. 이것만으로 사람은 **무게, 마찰, 저항**을 느낀다(HCI에서 검증된 기법).

- **무거운 부품 드래그**: 커서가 마우스보다 느리게 따라온다 → 무겁다.
- **토크렌치**: 규정 토크에 다가갈수록 C/D가 떨어지며 저항이 커지다가, 규정값에서 '딸깍' + **커서가 앞으로 툭 튀어나감**(렌치 슬립) + 플래시 + 진동.
- **디텐트 노브와 페이더**: 디텐트 사이에서 커서가 홈으로 빨려 들어가는 자석 효과.
- **마스터 스위치(프롤로그)**: 누르는 깊이에 따라 저항이 커지다가 넘어가는 순간 해방.
- 드래그 인터랙션은 Pointer Lock을 우선 사용(Artifact iframe에서 막히면 가상 커서 방식으로 폴백).

### 9.5 실제 진동

## 10. 사운드 디자인

### 10.0 도하 피드백 반영 (2026-10-02, P0 청음)

- **체결음 목표 = '철컥'**: 경화강 폴이 걸리는 밝은 '철' + 패널이 하드 스톱에 안착하는 단단한 '컥' + 미세 바운스. '뚱'(저역 위주)은 금지. 상세: [`reviews/P0-platform.md`](reviews/P0-platform.md) §6.
- **부품과 물성마다 다른 소리**: 체결음 파라미터는 부품 크기·두께·질량·접촉 재질에서 계산한다(같은 소리 재사용 금지, 변주는 시드).
- **나사 체결 = 로봇팔 너트러너**: 모터음, 유성기어 맞물림음, 토크 상승, 클러치 이중 클릭.
- **유압 부품 = 유압음**: 밸브 포핏 클릭, 펌프 맥동, 유량 히스, 안착음.
- 출력 지연이 큰 환경(블루투스, 약 170 ms 실측, 도하 확인)에서는 화면의 충격 효과를 소리에 맞춰 늦춘다.
- **질감 원칙 (2차 청음)**: 모든 소리는 '조금 거칠게'. 음높이를 바꾸지 않고 **층을 겹쳐서** 만든다(탈조 층의 맞놀이, 20~150 Hz 진폭 변조, 미세 충격 덜컥거림/그릿/기포). 체결음 '철컥' 3종은 승인됨.
- **유압 소리는 v2로 확정** (3차 청음: 도하가 v3 '슉'보다 v2를 선택). 밸브 클릭 + 펌프 맥동 + 유량 히스 + 안착음.
- **확정 소리 (P0)**: 체결 '철컥' v3(부품별 파라미터), 로봇팔 너트러너 v3, 유압 v2. 코드: `spikes/p0-platform/src/sfx.js`.

### 10.1 원칙

1. **소리도 물성에서 나온다.** 패널의 크기, 두께, 재질, 접촉 상태가 소리를 결정한다.
2. **반복은 기계처럼 들린다.** 모든 이벤트에 변주(피치 ±3%, 게인 ±1.5 dB, 레이어 조합 랜덤)를 준다.
3. **소리가 공간에 있다.** 부품이 체결되는 3D 위치에서 들린다(HRTF 패닝).
4. **음악보다 기계음이 주인공.** 스코어는 최소한으로.

### 10.2 엔진 구조

```
[이벤트 버스] → SoundEvents 매퍼 (부품 메타데이터 → 파라미터)
   ├─ ModalSynth (AudioWorklet): 패널 공명
   ├─ MotorSynth: BLDC 와인 (각속도 연동, 극쌍 × rpm 고조파 + 기어 메시 주파수)
   ├─ HydraulicSynth: 펌프 맥동, 유량 히스(속도 연동), 밸브 틱
   ├─ GranularRatchet: 고속 스크롤 시 체결음 스트림
   ├─ Sampler: 소량의 유기적 텍스처 샘플
   └─ Spatializer (PannerNode HRTF)
        ↓
 버스: Mechanical / UI / Ambience / Score  →  사이드체인 더킹  →  컨볼루션 리버브 (합성 IR: 소형 스튜디오, 행거)  →  리미터  →  출력
```

- 지연: AudioContext `latencyHint: 'interactive'`, 버퍼를 미리 디코드. 목표 이벤트 → 소리 20 ms 이하.
- 보이스 관리: 동시 발음 수 제한, 보이스 스틸링, 고속 연쇄 시 그레인 래칫으로 전환(원칙 L).

### 10.3 합성 기법

- **모달 합성**: 판의 고유진동수 근사 f ∝ (t / a²) · √(E / ρ(1−ν²)) × 형상/곡률 계수. 티타늄 E = 113.8 GPa, ρ = 4,430 kg/m³, ν = 0.34. 히어로 부품은 **FEM 고유치 해석**(선택)으로 실제 모드를 뽑는다. 아이솔레이터 위 패널은 감쇠가 크게(T60 0.05~0.2 s), 금속끼리 닿는 부품은 길게.
- **여기(excitation) 모델**: 접촉 경도(Ti-Ti, Ti-엘라스토머, Ti-폴리머 가이드)에 따라 여기 스펙트럼을 바꾼다.
- **모터**: 실제 시뮬레이션 각속도로 구동되는 실시간 합성 → 슈트가 움직이는 만큼 정확히 소리가 난다.
- **유압**: 펌프 맥동(피스톤/기어 수 × rpm) + 필터링된 노이즈 히스(유량 비례) + 릴리프.

| 분류 | 내용 |

### 10.5 믹스 기준

- 통합 음량 **−18~−16 LUFS**, 트루 피크 **−1 dBTP 이하**.

- 마스터 볼륨과 버스별 볼륨(설정 패널).

### 10.6 검증 (정직하게: 나는 소리를 직접 들을 수 없다)

- OfflineAudioContext로 헤드리스 렌더 → WAV → **스펙트로그램 이미지를 직접 보고** 어택, 감쇠, 대역, 음량(LUFS), 크레스트 팩터를 분석한다.

- **최종 판단은 도하의 귀**: G3(버티컬 슬라이스)와 G6(사운드 베타)에서 청음 체크리스트로 피드백을 받는다.

### 11.3 로딩 전략

1. HTML/CSS/JS 셸 + 프롤로그 스위치(약 1.5 MB) → 즉시 상호작용 가능.
2. 프롤로그 동안 히어로 에셋(10 MB 이하) + GPU 벤치마크.
3. 스크롤 진행 방향으로 다음 2개 챕터의 에셋을 선제 로드.
4. 오디오: 합성 엔진은 즉시, 샘플은 프롤로그 중에 디코드.

### 11.4 Artifact 발행 제약과 대응

| 제약 | 대응 |
|---|---|
| 파일당 텍스트 16 MB, 바이너리 15 MB | glTF 청크 분할, 텍스처 분할 |
| 1회 발행 255개 파일, 64 MB / 버전당 511개, 256 MB | 총 60 MB 이하 목표. 넘으면 같은 URL에 여러 번 나눠 발행 |
| 외부 스크립트 CDN 제한 | Vite가 전부 번들 → 외부 의존 없음 |
| 표준 웹 미디어 타입만 | wasm(basis 트랜스코더)의 MIME 허용 여부 스파이크 확인. 안 되면 meshopt(JS 내장) + WebP 텍스처로 폴백 |
| iframe 샌드박스 가능성 | WebGPU, AudioContext, Pointer Lock, Vibration, DeviceOrientation 가용성을 **P0 스파이크에서 실측** |
| 기본 비공개 | 공개 범위는 도하가 결정 |
| (R2) 플레이트 영상 용량 | AV1 14 MB 청크, 데스크톱 약 140 MB, 모바일 약 98 MB → 같은 URL에 3회 분할 발행(버전당 256 MB 안) |
| (R2) WebCodecs와 영상 MIME | P2 스파이크에서 실측. 폴백 `<video>` 시킹 → WebP 시퀀스 |
