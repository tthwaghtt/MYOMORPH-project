## 1. 브리프 해석: 지킬 것, 바꿀 것, 더할 것

### 1.1 그대로 지키는 것 (도하 의도의 핵심)

- 근육군 단위로 나뉜 **분절 금속 패널**이 전신을 덮는다. 통짜 흉갑은 쓰지 않고 **좌우 가슴근을 별도 패널**로 만든다.
- 패널은 껍데기에서 끝나지 않는다. 힘 전달, 보호, 수납, 냉각, 모듈 교체, 상태 표시 역할을 나눠 맡는다.
- 관절을 가로질러 고정되는 큰 판은 없다. 겹치고 미끄러지는 구조로 만들고, 겹침 방향은 근육 결을 따른다.
- 목과 허리는 분절형 **수동** 구조. 능동 구동은 후속 검토 항목으로 남긴다.
- 구동 배치(유압/전기+케이블)는 브리프 §4 표를 출발점으로 삼는다.
- 기능 5종: 전완 툴 베이, 교체형 근육 패널, **아래쪽으로 열리는** 냉각 루버(가슴, 등/승모, 둔근에 통합. 갈비뼈 모양 루버 금지), 전완 아래 보조 손, 근섬유 방향 상태 표시(색과 패턴 병행).
- 착용자 178 cm / 윙스팬 182 cm / 65 kg / BMI 20.5. V자 실루엣, 좁은 골반, 길고 가는 목과 팔다리.
- 공학 고증 최대. 단 하나의 예외는 **배터리 에너지 밀도를 10년 후(2036년) 수준으로 가정**하는 것(도하 지정).
- 금속은 티타늄과 골드티타늄 계열.
- three.js와 Blender 모두 사용. Vite 빌드. AgX. 풍부한 사운드. 모든 UI에 모션. 커서 상호작용과 스크롤 상호작용.

### 1.2 바꾸거나 다듬는 것 (판단과 이유)

| # | 브리프 원문 | 나의 판단 | 이유 |
|---|---|---|---|
| 1 | 스크롤 약 100초 이상 | **목표 약 226초**. 분량을 늘리려고 늘리지는 않는다. 모든 비트가 존재 이유를 가져야 하고, 챕터 점프와 건너뛰기를 제공한다 | 본편인 패널 조립만 해도 60초가 필요하다. 길이보다 **리듬**(느린 단독 체결 ↔ 빠른 연쇄 체결)이 지루함을 막는다 |
| 2 | "CES 대신 AgX" | ACES로 이해했다. AgX에 동의하고 한 단계 더 간다: Blender의 AgX를 OCIO로 **3D LUT로 베이크**해서 three.js에 적용 | three.js 내장 `AgXToneMapping`은 Blender의 OCIO 구현과 미세하게 다르다. LUT를 쓰면 픽셀 단위로 일치시킬 수 있다. ACES는 상태광 같은 고채도 발광체에서 색이 틀어지고(파랑이 보라로) 클리핑이 생긴다. AgX는 밝아질수록 자연스럽게 백색으로 수렴한다 |
| 3 | three.js와 블렌더 모두 | 역할을 분명히 나눈다. **Blender = 형상, 메타데이터, 베이크, 레퍼런스 렌더, HDRI의 '진실의 원천'**. **three.js = 실시간 재현과 상호작용**. 조립 애니메이션은 Blender 키프레임으로 만들지 않고, Blender가 내보낸 **조립 데이터(JSON)로 런타임에 절차적으로 생성**한다 | 스크롤을 거꾸로 올려도 완전히 되돌아가야 하고, 용량을 줄여야 하며, 속도에 반응하는 사운드와 연동해야 하기 때문 |
| 4 | 모든 버튼, 입력란에 모션 | 동의. 여기에 **MYO-UI 컴포넌트 체계**를 더한다. 모든 UI가 실제 기계 부품(토글, 페이더, 로터리 노브, 각인 입력판)의 물리를 따른다 | 장식용 모션은 '그림티'를 낸다. 물리를 따르는 모션은 손맛을 만든다 |
| 5 | 손맛 | 3겹 전략: ① 오디오와 비주얼의 ms 단위 동기(히트스톱, 카메라 임펄스, 접촉 하이라이트) ② **의사 햅틱**(커서 이동 비율을 조작해 무게, 저항, 딸깍을 '느끼게' 하는 HCI 기법) ③ 실제 진동(Vibration API, 지원 기기) | 데스크톱 마우스에는 진동이 없다. 손맛의 대부분은 ①과 ②에서 나온다 |
| 6 | 블렌더 고인물 방법론 조사 후 보고 | 그대로 한다. 결과물은 **MYOMORPH Blender Standard(MBS)** 규약집으로 만들고, 이후 모든 스크립트가 이 규약을 자동으로 검사(린트)한다 | 조사가 보고서로 끝나지 않고 작업 품질을 강제하는 장치가 된다 |
| 7 | 드로잉 = 1순위 레퍼런스 | 유지. 실측해 보니 실제 착용 치수와 놀라울 만큼 가깝다. 다만 **4곳만 소폭 수정**을 제안한다(§2) | 착용 가능성(공학 고증)과 도하의 비율을 함께 지키기 위해 |
| 8 | 헬멧(드로잉) | **실루엣과 비율은 유지하고 디테일은 오리지널로**. 안면근 해부도를 기반으로 한 마스크 'PERSONA'(§5.7). ✅ 도하 확정 (2026-10-01) | 드로잉의 헬멧은 기존 유명 IP를 강하게 연상시킨다. 포트폴리오에서는 리스크가 되고, 우리 콘셉트(근육 해부도)와도 더 잘 맞는다. 마스크 디자인은 브리프에서도 미확정 항목이다 |
| 9 | 풍부한 사운드 | 샘플 위주가 아니라 **물리 기반 합성** 중심. 부품의 실제 치수, 두께, 티타늄 물성으로 고유진동수를 계산해서 소리를 만든다 | 큰 패널은 낮고 묵직하게, 작은 부품은 높고 날카롭게. 공학 고증이 소리에까지 닿는다 |

### 1.3 내가 더하는 것 (새 아이디어)

| 코드 | 아이디어 | 한 줄 설명 |
|---|---|---|
| **A** | **기능적 해부학 일치 원칙** | 각 액추에이터는 **같은 일을 하는 인간 근육의 자리**에 둔다. 무릎 실린더는 대퇴사두근 패널 아래, 발목 실린더는 비복근 패널 아래(아킬레스건 = 실제 링크), 손가락 모터는 전완(인간도 손가락 근육이 전완에 있다), 손가락 케이블은 손목의 '수근관'을 지난다. 브리프의 구동 배치가 이미 인체 해부학과 일치한다는 점을 서사의 축으로 삼는다 |

| **L** | **속도 적응형 사운드** | 천천히 스크롤하면 체결음이 하나하나 온전히 울리고, 빠르게 스크롤하면 그레인 합성 래칫 소리('드르르륵')로 자연스럽게 넘어간다. 소리가 겹쳐 깨지는 현상을 막는다 |
| **M** | **모든 숫자는 계산서에서** | 사이트에 나오는 질량, 토크, 전력, 열 수치는 전부 `engineering/` 계산 스크립트가 만든 `engineering.json` 하나에서 나온다. 빌드할 때 자동으로 대조한다 |
| **N** | **툴 카메라 PIP** | 툴 베이의 점검 카메라가 꺼지면 **그 카메라 시점에서 실제로 렌더한 화면**이 PIP로 뜬다 |

## 2. 레퍼런스 드로잉 실측 분석

### 2.1 방법

1. 드로잉에서 진한 파란 선 픽셀을 추출하고, 3px 팽창한 뒤 외부를 플러드필해서 **본체 실루엣**만 분리했다(측면 상세 박스는 제외).

## 3. 크리에이티브 콘셉트

### 3.1 이름이 곧 콘셉트

**MYOMORPH = myo(근육) + morph(형태)**. "근육의 형태를 가진 기계."  
카피 축: **"NOT ARMOR. ANATOMY."** / **"피부 아래의 설계도."**

### 3.2 '근골격 슈트'의 공식 정의

외골격(갑각)은 단단한 껍데기가 몸을 가둔다. **MYOMORPH의 근골격 구조**는 인체처럼 층을 이룬다. 하중은 착용자의 뼈 축을 따라가는 가는 **프레임(뼈)**이 받고, 힘은 **케이블과 유압(힘줄과 근육)**이 만들고, 동작의 자유는 **근육군 단위로 쪼개진 금속 패널(근육 외형)**이 만든다.

### 3.3 디자인 원칙 7

1. **갑옷이 아니라 근육.** 모든 형상은 근육의 덩어리, 방향, 경계에서 나온다.
2. **물리적 원인이 없는 효과는 금지.** 번쩍임은 실제 광원의 반사, 흔들림은 실제 질량의 충격, 소리는 실제 부품의 물성에서 나온다.
3. **모든 부품에는 이유가 있다.** 역할 태그(§5.3) 없는 부품은 만들지 않는다.
4. **기능적 해부학 일치.** 기계의 근육은 인간 근육이 있는 자리에 있다.
5. **정밀함이 곧 장식.** 밀도는 소음이 아니라 정보로 읽혀야 한다(부품번호, 공차, 체결 규격).
6. **질량을 가진 모션.** 기본 트윈과 선형 이징은 금지. 스프링, 관성, 감쇠로 움직인다. 무거운 부품은 느리고 묵직하다.
7. **엔지니어의 문법으로 말한다.** ISO 도면 문법(리더선, 벌룬, 치수선, 일점쇄선 중심선, 표제란), SI 단위, 부품번호 체계.

- **모션**: 0.2 Hz로 숨 쉬듯 맥동하는 상태광. 유압 유닛의 낮은 험.
- **커서 상호작용**(§9.1): **점검 조명**(커서 방향으로 빛이 패널을 훑음), **시선 추적**(마스크가 커서를 따라 돌고 목 라멜이 실제로 미끄러짐), **근접 긴장**(커서 근처 패널이 0.5~1 mm 긴장하고 상태광이 밝아짐), **호버 콜아웃**(부품번호, 재질, 질량, 역할), **길게 클릭**(이두근 수축과 키네틱 벌지).
- **사운드**: 룸톤, 유압 험, 커서가 패널을 지날 때 미세한 서보 틱.
- **스크롤 안내**: 줄자/버니어 캘리퍼스 형태의 인디케이터.

#### 01. SCHEMA (모든 기계는 스케치에서 시작한다)
- **화면**: 카메라가 **돌리 줌으로 원근에서 정사영으로** 바뀌며 정면에 선다. 슈트가 블루프린트 선화(에지 검출 셰이더)로 바뀌고 배경에 코발트 그리드가 깔린다. **도하의 원본 드로잉**이 겹치며 정렬된다(크레딧 표기, 도하 승인 필요).
- **모션**: 치수선(178 / 182 / 65)이 그려진다. 드로잉의 상세 박스(HELMET FRONT/SIDE, SHOULDER, CHEST, FOREARM, HAND, REAR VIEW)가 **실시간 3D 인셋 뷰포트**로 변한다.
- **사운드**: 펜 플로터의 서보음과 펜 긁힘.
- **카피**: "모든 기계는 한 장의 스케치에서 시작한다. — Original sketch by 도하"

#### 02. CORPUS (착용자)
- **화면**: 같은 자세의 중립 회색 착용자 마네킹(178/182/65, BMI 20.5). 인체 측정선. **스캔 평면이 몸을 훑으면 피부가 벗겨지고** 반투명한 섬유 질감의 근육 지도(écorché)가 드러난다. 라틴어 근육명 콜아웃.
- **사운드**: 의료 스캐너 스윕, 저음 드론.
- **카피**: "피부를 벗기면, 설계도가 보인다." / "BMI 20.5. 마른 몸에 맞춘 근육."

#### 03. FASCIA (라이너)
- **화면**: 검은 테크니컬 스페이서 메시 슈트가 몸 위에 형성된다(스티칭, 패브릭 시인 셰이더). 티타늄 하드포인트 인서트가 작게 '틱틱' 박힌다. 체결감을 처음 맛보는 구간.

#### 04. OS (프레임 = 뼈)
- **화면**: 대퇴골, 경골, 상완골, 요척골, 척추를 따르는 티타늄 프레임. 3D 프린팅 노드(격자 구조가 보이는 단면), 관절 축 일점쇄선, 베어링 압입. 무릎의 **순간회전중심(ICR) 궤적** 도해.
- **모션**: 분해 상태에서 조립. 베어링 압입은 묵직한 '퉁'.
- **카피**: "하중은 착용자의 뼈가 아니라, 슈트의 뼈로 땅에 내려간다."

#### 05. TENDO · MUSCULUS (구동계)
- **화면**: 몸통 안의 어깨 모터 + 파동기어 감속기 → 케이블이 삼각근 패널 아래로 지나감. 전완 모터 → 손목 '수근관' → 손가락. 팔꿈치, 고관절, 무릎, 발목 실린더.
- **핵심 연출(원칙 A)**: 반투명 인간 근육(유령)이 같은 자리의 기계 액추에이터로 **모핑**된다. 이두근이 실린더로, 비복근과 아킬레스건이 발목 실린더와 링크로. **"같은 자리, 같은 일."**
- **상호작용**: 스크롤에 따라 팔꿈치 각도와 실린더 스트로크 그래프가 실시간으로 그려진다.
- **사운드**: 서보 와인, 케이블 텐션 '지익', 실린더 슬라이드.

#### 06. COR · VASA (심장과 혈관)
- **화면**: 허리 뒤쪽의 HPU(심장)에서 펌프가 돌기 시작한다. 압력 맥동이 **심장 박동처럼** 뛴다. X-ray로 배관에 유체가 흐르고, 광배근 자리에 배터리 모듈이 '철컥' 들어간다. 동력 흐름도(배터리 → 펌프 → 밸브 → 액추에이터)에 실시간 수치.
- **사운드**: 펌프 스풀업, 밸브 솔레노이드 틱, 압력 히스, 배터리 래치.
- **카피**: "배터리 에너지 밀도는 2036년 기준 가정치." (도하 지정 예외를 투명하게 표기)

#### 07. MYOMORPH (근육 패널 조립, 본편 60초)
- **조립 순서**(실제 조립 논리 = 하부에서 상부로, 안에서 밖으로):  
  7a 발/종아리(아킬레스 링크) → 7b 무릎(슬개 캡 라멜) → 7c 대퇴(사두근, **봉공근 사선 띠**) → 7d 골반/둔근(루버) → 7e 복부(복직근 8분절이 척추처럼 쌓이고 외복사근 슬랫이 맞물림) → 7f 등(척추기립근, 광배근 배터리 커버, 승모 루버) → 7g 가슴(**대흉근 섬유 스트립이 흉골에서 상완골 쪽으로 부채꼴로 들어옴**) → 7h 어깨(삼각근 3두와 라멜) → 7i 상완(이두, 삼두) → 7j 전완(툴 베이와 보조 손 커버) → 7k 손(지골 판의 초고속 연쇄 '타라라락') → 7l 목(라멜이 척추처럼) → **7m PERSONA: 마스크가 닫힌다**
- **자동 조립 셀 (도하 피드백, 2026-10-02)**: 슈트 주위의 천장 갠트리와 6축 로봇팔들이 부품을 집어 오고, **너트러너(드릴) 엔드 이펙터가 직접 나사를 조인다**. 모터음과 클러치 클릭이 들리고, 유압 부품은 장착 직후 시험 구동하며 유압음을 낸다. 로봇팔은 블랙 아노다이즈 + 시그널 오렌지 안전 표식으로 슈트(티타늄)와 대비. 모델링 범위(P4)와 부품·성능 예산에 로봇팔 4~6대를 추가한다.
- **카메라**: 매크로(100 mm, 얕은 심도)와 와이드를 교차. 중간에 **하이퍼랩스 오비트 한 번**: 6초 동안 200장이 연쇄 체결되는 '압도' 구간.
- **리듬**: 히어로 부품(대흉근, 삼각근, 배터리, 마스크)은 느린 단독 체결 + 스크류 구동 + 콜아웃. 나머지는 연쇄 체결.
- **실시간 카운터**: 장착 부품 수, 누적 질량(kg), 토크 완료 체결부품 수.
- **클라이맥스**: 마스크의 2단 체결 + 최대 히트스톱(약 90 ms) + 저역 '쿵' → 바이저 점등 → 상태광이 마스크에서 발끝까지 흘러내리며 08로 이어진다.

#### 08. NERVUS (신경계 부팅)
- **화면**: 근섬유 광선이 기시에서 정지 쪽으로 흐른다. 상태 패턴 범례를 각 근육 위에서 하나씩 시연(§5.6). 라이너의 EMG 전극이 착용자 근육 신호를 읽으면 같은 기계 근육이 빛난다.
- **카피**: "당신의 근육이 신호를 보내면, 기계의 근육이 답한다."

#### 09. MOTUS (관절 가동)
- **화면**: 목 회전(라멜 슬라이딩), 몸통 굴곡과 비틀기(복부 분절 텔레스코핑), 팔 들기(삼각근 라멜), 스쿼트(폴리센트릭 무릎). **키네틱 벌지**(이두근, 비복근). 간섭 여유 히트맵 오버레이. 관절 각도 vs 액추에이터 스트로크 그래프.
- **상호작용**: **팔을 잡고 굽히기**. 전완을 드래그하면 팔꿈치가 굽는다. 실린더 로드가 미끄러지고, 유압음이 속도에 비례하고, 커서가 무겁게 따라온다(의사 햅틱).

#### 10. FUNCTIO (기능 모듈)
- **10a 툴 베이**: 전완 신근 패널이 원위 방향으로 미끄러지며 열린다. 툴 카트리지에서 작업등(**실제 광원으로 장면을 비춤**), 점검 카메라(**PIP에 그 시점의 실시간 렌더**), 드라이버 비트(회전)가 나온다. 무거운 공구는 팔꿈치 쪽에 둔다.
- **10b 보조 손**: 전완 아래에서 펼쳐진다. 정밀 모드로 M2 나사를 집고, 와이드 모드로 원통을 감싸 쥔다. 하중 경로(손목이 아니라 전완 프레임으로) 시각화.
- **10c 교체 패널**: 광배근 배터리 패널이 쿼터턴 래치 해제 → 포고핀 노출 → 슬라이드 아웃. 새 모듈 장착, SOC 표시. 골반 버퍼 셀 덕분에 시스템이 꺼지지 않는다(핫스왑).
- **10d BRANCHIA**: 대흉근, 승모/등, 둔근 루버가 **아래로** 단계적으로 열린다(아가미). **열화상 모드 토글**(아이언 팔레트)로 열이 빠지는 것을 본다. 일반 모드에서는 배기구 근처에 **열 아지랑이(굴절 왜곡)**가 보인다. 블로워 스핀업 소리.
- 각 모듈은 스크롤로 진행되지만 **MYO-UI 버튼으로 직접 작동**시킬 수도 있다.

#### 11. DOSSIER (데이터)
- **화면**: 엔지니어링 사양서. 치수, 질량 예산(서브시스템별 누적 막대), 전력 예산, 가동 시간(2036 배터리 가정 표기), 관절 ROM 표, 액추에이터 표, 부품 수. 분해 액소노메트릭 뷰 + BOM 벌룬.
- **상호작용**: BOM 행에 호버하면 3D 부품이 하이라이트되고, 3D 부품에 호버하면 BOM 행이 하이라이트된다(양방향 연결). 숫자는 오도미터처럼 굴러간다.

#### 12. MK. 1 / INSPECT (피날레와 자유 탐색)
- **기능**: 관성과 디텐트가 있는 오비트, 관찰 모드 4종, **분해 슬라이더**, 마감 전환(티타늄 ↔ TiN 골드), **Fit-to-You 컨피규레이터**, 부품 검색 입력란("biceps"라고 치면 그 부품으로 날아감), **토크렌치 미니 인터랙션**, 크레딧.
- **크레딧(가안)**: Concept & Design Intent: 도하 / 3D · Motion · Sound · Engineering: Claude
- **맨 위로**: 슈트가 전원을 내리며(상태광이 발끝부터 꺼짐) 프롤로그로 돌아간다.

## 5. MYOMORPH-MK. 1 엔지니어링 바이블 (초기안)

> 아래 수치는 모두 **초기 추정치**다. P1에서 `engineering/` 계산서(Python)로 검증하고 확정하며, 사이트의 모든 숫자는 그 계산서 출력 하나에서만 나온다.

### 5.1 좌표계, 단위, 명명

- 단위: SI, **1 Blender unit = 1 m**. 모든 트랜스폼 적용. +Z up(Blender) → +Y up(glTF).
- 원점: 두 발 사이 바닥. 정면 = −Y(Blender).
- 부품번호: `MM1-[부위]-[근육/부품]-[L|R|C]-[NN]`  
  예: `MM1-TH-RF-L-02` (대퇴, 대퇴직근, 왼쪽, 패널 02), `MM1-FA-TB-R-COV` (전완 툴 베이 커버).
- 부위 코드: HD(머리), NK(목), CH(가슴), AB(복부), BK(등), SH(어깨), UA(상완), FA(전완), HN(손), PV(골반), TH(대퇴), KN(무릎), SK(하퇴), FT(발), IN(내부).

### 5.2 서브시스템 트리 (BOM 상위)

```
MM1 (MYOMORPH-MK. 1)
├── PERSONA   마스크 (안면근 패널, 바이저, 측두 허브, 넥 실)
├── MYO       근육 패널 (~550장, 서브 패널, 라멜, 루버 슬랫 포함)
├── OS        프레임 (LPBF 노드, 튜브, 관절, 베어링, 기계식 하드 스톱)
├── TENDO     케이블 구동 (모터, 감속기, 캡스턴, 풀리, 보든 케이블, 텐던)
├── MUSC-H    유압 액추에이터 (실린더 8: 팔꿈치 2, 고관절 2, 무릎 2, 발목 2)
├── COR       유압 동력 (HPU, 축압기, 저장조, 매니폴드, 서보밸브, 배관, 피팅)
├── ENERGIA   전원 (광배근 배터리 모듈 2, 골반 버퍼 셀, BMS, 배전)
├── BRANCHIA  냉각 (루버 3계통, 개폐 액추에이터, 블로워, 핑거프루프 메시)
├── NERVUS    감지/표시 (IMU, 하중셀, 엔코더, EMG, 하네스, 상태광 라이트파이프)
├── FUNCTIO   기능 모듈 (툴 베이, 보조 손, 교체 패널 인터페이스)
├── FASCIA    라이너 (스페이서 메시, 하드포인트, 커프, 스트랩)
└── FIX       체결부품 (~2,500~4,000: 접시머리 Torx, 쿼터턴 패스너, 리벳, 핀)
```

**부품 수 목표**: 근육 패널 약 550 + 내부 기계 약 700 + 체결부품 약 3,000 = **약 4,000개 이상**. 좌우 대칭이라 고유 메시는 약 600종.

### 5.3 근육 패널 분할 규칙

**식별 근육(한쪽 기준, 약 45개)**  
머리/목: 전두근, 측두근, 교근, 안륜근, 구륜근, 흉쇄유돌근, 판상근 · 몸통 앞: 대흉근(쇄골두/흉늑두), 전거근, 복직근(8분절), 외복사근 · 등: 승모근(상/중/하), 광배근, 대원근, 극하근, 척추기립근 · 어깨: 삼각근(전/중/후) · 상완: 이두근, 상완근, 삼두근(장/외측/내측두) · 전완: 완요골근, 요측수근신근, 지신근, 수근굴근군, 원회내근 · 손: 무지구, 소지구, 배측골간근, 지골 · 골반: 대둔근, 중둔근, 대퇴근막장근 · 대퇴: 대퇴직근, 외측광근, 내측광근, 봉공근, 내전근군, 대퇴이두근, 반건양근 · 하퇴: 전경골근, 장비골근, 비복근(내/외측두), 가자미근, 아킬레스 링크 · 발: 족배 판, 밑창

**역할 태그** (모든 패널에 1개 이상. 브리프 §7-2 반영)

| 태그 | 의미 | 예시 |
|---|---|---|
| **D** | 조형 (근육 표현) | 대부분의 표면 패널 |
| **P** | 보호 | 슬개 캡, 정강이, 전완 신근 |
| **F** | 힘 전달 / 구조 | 실린더 마운트 패널, 보조 손 기부 |
| **M** | 기능 모듈 | 배터리(광배근), 툴 베이, 센서 패널 |
| **S** | 슬라이딩 / 관절 | 목, 복부, 삼각근, 무릎 라멜 |
| **V** | 냉각 루버 | 대흉근, 승모근/등, 둔근 슬랫 |
| **L** | 상태광 | 근섬유 홈 라이트파이프 |

**분할 규칙**
1. **이음선 = 근육 사이의 골.** 인접 근육 형상 중 어느 쪽에 더 가까운지로 표면 소유권을 나누고, 그 경계를 패널 이음선으로 쓴다. 해부학적 근간 홈과 정확히 일치한다.
2. **근육 내부는 섬유 방향으로 분할한다.** 큰 근육(대흉근, 광배근, 대둔근)은 섬유를 따라 3~7개 스트립으로 나눈다. 이 스트립 사이 홈에 상태광 라이트파이프가 들어가고, V 태그 패널은 루버 슬랫이 된다.
3. **관절을 가로지르는 단일 강체판 금지.** 자동 검사: 하나의 강체 패널이 두 뼈 영향권에 걸치면 실패.
4. **겹침 방향 = 지붕 기와 원칙.** 위쪽 패널이 아래쪽 패널 위에 오도록 겹쳐 빗물과 먼지가 흘러내리게 한다. 관절에서는 굴곡할 때 열리지 않는 쪽으로 겹친다.
5. **간격**: 일반 1.5 mm(±0.2 mm 제조 공차를 시드 기반으로 무작위화), 슬라이딩 2.5 mm, 루버 개방 시 최대 8 mm.
6. **두께**: Ti-6Al-4V **0.8~1.2 mm**, 강성은 프레스 비드(보강 리브)와 헴(가장자리 접기)으로 확보.
7. **가장자리**: 바깥 모서리 0.4 mm 챔퍼 + 필렛, **안쪽으로 접힌 플랜지/헴 2~4 mm**(판금 실사감의 핵심).
8. **고정**: 패널은 엘라스토머 아이솔레이터 위에 떠서 프레임 하드포인트에 고정된다(진동/소음 감쇠 + 공차 흡수). 슬라이딩 패널은 UHMW-PE 슬라이드 패드 + 가이드 핀. 착용자 피부와 옷이 끼지 않도록 내측 보호 스커트를 둔다.

### 5.4 부위별 구동 배치 (브리프 §4 확장 + 원칙 A)

| 부위 | 구동 | 인체 근육 대응 | 설계 디테일 |
|---|---|---|---|
| 어깨 | 몸통 쪽 BLDC + 파동기어 감속기 → 캡스턴 → 케이블 | 대흉근, 광배근, 승모근이 팔을 당기듯 | 2축 능동(굴곡, 외전), 나머지는 수동. **견갑 운동으로 이동하는 관절 중심을 따라가는 자기정렬 수동 자유도**(실제 외골격의 핵심 난제) |
| 팔꿈치 | 복동 유압 실린더 (상완 전면) | 이두근, 상완근 | 실린더 배럴 피벗 → **키네틱 벌지**. 0~135° |
| 손목, 손가락 | 전완 근위부 마이크로 BLDC + 캡스턴 → 텐던 | 전완 굴근군, 신근군 | 손목 '수근관' 케이블 가이드. 무거운 것은 팔꿈치 쪽 |
| 골반, 고관절 | 골반 = 구조와 모듈 배치부. 굴곡/신전은 유압 | 장요근, 대둔근 | 외전/회전은 수동 + 케이블 보조. 기계식 하드 스톱 |
| 무릎 | 복동 유압 실린더 (대퇴 전면) | 대퇴사두근 | **폴리센트릭 4절 링크**로 ICR 추종(단순 경첩 아님). 0~125° |
| 발목 | 종아리 쪽 복동 유압 실린더 → 아킬레스 링크 → 뒤꿈치 레버 | 비복근, 가자미근 | 내번/외번은 수동 + 엘라스토머 센터링. 무거운 부품은 종아리에 |
| 허리 | 분절형 수동 패널 (초기) | 복직근, 복사근 | 저토크 케이블 능동 보조는 후속 검토 |
| 목 | 분절형 수동 라멜 | 흉쇄유돌근, 목덜미 인대 | 능동 구동 없음 |

**초기 사이징 예** (P1에서 확정): 실린더 내경 16~20 mm, 작동압 21 MPa급 → 16 mm에서 추력 약 4.2 kN, 모멘트암 30 mm에서 약 127 N·m (무릎 요구치 90~120 N·m을 충족).

### 5.5 동력 흐름과 유압 회로

`배터리(광배근) → 배전/BMS → BLDC 모터 → 내접기어 펌프 → 축압기 → 중앙 매니폴드(허리) → 관절 근처 분산 서보밸브 → 실린더 → 리턴 → 저장조(부트스트랩식)`

- HPU 위치: **허리 뒤쪽, 천골 부근**(무게중심에 가깝고 둔근 루버로 냉각).
- 배관: 척추와 사지를 따라 혈관처럼 라우팅. 압력선과 리턴선은 피팅 색 밴드로 식별(실제 현장 관행).
- 안전: 릴리프 밸브, 관절마다 기계식 하드 스톱(인간 ROM 이내), 흉골 마스터/비상정지 스위치(프롤로그의 그 스위치).
- 브리프 §5.2 준수: 유압 배관이 포함된 모듈은 현장 교체 대상에서 제외(압력 격리 설계 전까지).

### 5.6 기능 모듈

**툴 베이 (FUNCTIO-1)**: 전완 배측(요측) 신근 패널이 원위 방향으로 슬라이드한 뒤 피벗해서 열린다. 슬롯 레일 카트리지에 작업등(고연색 LED), 관절형 점검 카메라(5.5 mm 보어스코프), 1/4" 비트 드라이버(마이크로 기어모터). 무거운 것은 팔꿈치 쪽. 보조 손과 간섭하지 않도록 **툴 베이는 배측, 보조 손은 장측(척측)**에 둔다.

**교체형 근육 패널 (FUNCTIO-3)**: 공통 규격 'MYO-PORT'. 쿼터턴 패스너(항공기 패널 방식) + 가이드 레일 + 저전압 전원/데이터 포고핀 8핀. 모듈: 배터리, 공구, 센서, 냉각.

**냉각 루버 BRANCHIA**: 근섬유를 따라 3~7개 슬랫으로 분절하고, **아랫변이 바깥으로 젖혀져 개구부가 아래를 향한다**. 개구부가 아래를 향하면 비와 먼지를 막고 전면 상방 시선에서 내부가 가려진다. 공기는 블로워로 강제 순환하므로 부력 방향은 문제가 되지 않는다. 슬랫 하나당 액추에이터를 두지 않고 근육마다 소형 리니어 액추에이터 1개와 링크 바로 단계적으로 개방한다. 내부에 핑거프루프 메시. 계통: 대흉근 → 어깨 모터, 승모/등 → 연산부와 전자부, 둔근 → HPU와 고관절 밸브. 착용자 통풍과 장치 냉각 경로는 분리한다.  
열 검산: 운동 중 발열 약 400 W, 공기 온도 상승 20 K 기준 필요 유량 = 400 / (1005 × 20) ≈ 0.02 kg/s ≈ **16.5 L/s(약 35 CFM)** → 소형 블로워 여러 개로 충분.

**보조 손 (FUNCTIO-2)**: 전완 장측 패널 아래에 접혀 수납되는 2지 + 대향 엄지 어댑티브 그리퍼. 정밀 모드(패드 근접, 평행 조), 와이드 모드(텔레스코픽 확장 + 패드 회전). 기부는 손목이 아니라 **전완 프레임(척골 대응)**에 앵커링해 하중을 분산.

**상태 표시 NERVUS (가안, G1에서 확정)**

| 상태 | 색 | 패턴 |
|---|---|---|
| 정상 대기 | 백색 5600K | 상시 점등 |
| 스탠바이 | 백색 | 0.2 Hz 맥동 (호흡) |
| 구동 중 | 시안 (대안 비교 예정) | **기시 → 정지 방향 흐름, 속도와 밝기 ∝ 부하** |
| 온도 상승 | 앰버 | 1 Hz 느린 점멸 |
| 점검 필요 | 앰버 | 이중 점멸 |
| 고장/정지 | 레드 | 4 Hz 빠른 점멸 |

색만으로 구분하지 않고 패턴을 병행하므로 색각 이상 사용자도 읽을 수 있다(브리프 §5.5). 광원은 금속 패널 '속'이 아니라 섬유 스트립 사이 홈에 넣은 사파이어/PC 라이트파이프 + 측면 LED라서 공학적으로 성립한다.

### 5.7 마스크 PERSONA (오리지널 디자인 방향)

- **실루엣**: 드로잉의 타원형 헬멧, 넓은 바이저 영역, 측면 원형 디스크 비율 유지.
- **디테일 = 안면근 해부도**: 안륜근 링이 바이저 프레임, 관골근이 광대에서 입꼬리로 흐르는 패널, 교근이 턱관절 가드, **측두근 부채꼴 판이 측두 허브(귀 디스크)로 수렴**, 전두근 세로 스트립, 이근(턱).
- **기능**: 스모크 바이저(폴리카보네이트 하드코트, 외부에서 불투명), 측두 허브(골전도 마이크, 측면 카메라), 교근부 마이크로 벤트 + 블로워(김서림 방지), 넥 실.
- **체결**: 후두 셸 → 측두 부채판 → 안면판 하강 → 바이저 락. 2단 체결 = 07의 클라이맥스.

- **열변색(heat tint)은 '열이 실제로 나는 곳'에만 자연스럽게** 넣는다(원칙 2, 물리적 원인 없는 효과 금지):
  1. 프레임 노드와 튜브의 **TIG 용접부**: 비드 양옆 5~15 mm에 금색 → 청동 → 보라 → 청색 띠 (실제 티타늄 용접에서 생기는 그대로)
  2. HPU 배기 덕트 출구와 **둔근 루버(BRANCHIA) 안쪽 립**: 고온 배기가 지나는 가장자리
  3. 펌프 하우징 열차폐판, 유압 하드라인의 펌프 쪽 구간
  - 바깥 근육 패널 표면에는 넣지 않는다(손상처럼 보임). X-ray와 분해 장면, 루버가 열리는 순간에 드러나는 '숨은 디테일'로 쓴다.
  - 렌더링: 열변색은 산화막의 **박막 간섭**이라 보는 각도에 따라 색이 변한다. Blender Principled BSDF의 Thin Film(두께, IOR)과 three.js `iridescence`(두께 맵)가 같은 물리 모델이라 양쪽을 일치시킬 수 있다. 두께 맵은 열원에서의 거리로 절차 생성한다.

**실사 디테일로 쓰는 공정 흔적**: SPIF 성형은 패널 **안쪽 면에 나선형 공구 경로 자국**을 남긴다. 조립 중 패널이 뒤집혀 안쪽이 보이는 순간 이 자국이 보이면 '그림티'가 사라진다. 레이저 각인 부품번호, 데이터매트릭스 코드, QC 마크도 넣는다.

## 6. 실사화 전략: '그림티'를 지우는 법

'그림티'는 하나의 원인이 아니라 **여러 층의 작은 거짓말이 쌓인 결과**다. 층마다 막는다.

### 6.1 형상
- [ ] 실제 스케일(m)과 실제 두께. 떠 있는 부품이 없다.
- [ ] **날카로운 모서리 금지.** 모든 모서리에 0.3~0.5 mm 베벨을 두어 하이라이트 선을 잡는다(하드서피스 실사의 1번 원칙).
- [ ] 판금의 논리: 헴, 플랜지, 비드, 드래프트, 체결부, 아이솔레이터.
- [ ] 제조 공차: 간격 ±0.2 mm, 체결부품 회전각 무작위, 패널별 미세한 높이 차.
- [ ] 패널 안쪽 면도 모델링(SPIF 자국, 리브, 클립).

### 6.2 재질
- [ ] **측정 기반 PBR 값.** G0에서 n,k 분광 계산으로 확보(선형 sRGB): 티타늄 F0 기준선 (0.441, 0.400, 0.361) [Palm, physicallybased DB와 일치], 상한 (0.619, 0.579, 0.543) [J&C], **TiN (0.614, 0.462, 0.233)** [Pflüger]. 티타늄은 데이터셋 간 20~40% 차이 → P1 비교 렌더로 확정 (조사 보고서 §10).
- [ ] 비드블라스트 미세 노멀 + 거칠기 0.32~0.45, 폴리시 챔퍼 0.12~0.18.
- [ ] **근섬유 방향 이방성**(원칙 C): UV의 U축 = 섬유 방향 → 탄젠트가 섬유를 따름 → `anisotropy`.
- [ ] 거칠기 브레이크업: 지문과 취급 흔적은 5~10% 강도로 아주 약하게. 새 제품이므로 마모는 최소.
- [ ] 패널별 미세 편차: 로트 차이로 생기는 색상과 거칠기 ±2%(시드 기반).
- [ ] **스페큘러 앨리어싱 억제**(기하 스페큘러 AA): 고주파 노멀맵의 반짝거림은 CG의 대표적인 티다.

### 6.3 빛
- [ ] **Blender에서 직접 만든 스튜디오 HDRI**(스트립 소프트박스, 블랙 플래그)를 Blender와 three.js 양쪽에서 공용으로 사용 → 조명이 동일.
- [ ] 실시간 RectAreaLight로 스크롤에 따라 하이라이트가 패널을 **훑고 지나가는** 제품 공개 기법.
- [ ] 패널 간격의 접촉 그림자: 베이크 AO + 실시간 GTAO.
- [ ] 패널끼리의 상호 반사: SSR.
- [ ] 부드러운 그림자(PCSS 계열), 바닥 접지 그림자.

### 6.4 카메라와 후처리
- [ ] 실제 렌즈 파라미터(초점거리, 센서, 조리개) → 매크로에서 **물리적으로 맞는 피사계 심도**. 매크로 심도는 '크기의 실감'을 준다.
- [ ] **TAA(TRAA)**: 가는 패널 선과 서브픽셀 디테일의 깜빡임(시머링)을 없앤다.
- [ ] 모션 블러(속도 기반): 빠르게 날아드는 부품.
- [ ] 미세한 색수차, 비네팅, 노출 연동 필름 그레인.
- [ ] 블룸은 에너지 보존형으로 아주 약하게, 상태광에만 선택적으로.
- [ ] **AgX LUT**(§8.6). 과채도 금지.

### 6.5 모션
- [ ] 질량-스프링-감쇠 기반. 무거울수록 느리다. 기본 이징 금지.
- [ ] 접근 → 정렬(가이드 핀 미세 회전 보정) → 접촉 → 오버트래블 → 래치. 실제 조립 동작 그대로(§9.3).

### 6.6 맥락
- [ ] 부품번호, 각인, QC 마크, ISO 도면 문법 → '실제로 제작된 물건'이라는 맥락.
- [ ] 제품 사진의 구도와 조명 언어.

### 6.7 검증 (내가 직접 본다)
- 모델링을 반복할 때마다 **컨택트 시트 렌더**(정면, 측면, 후면, 3/4, 히어로 부위 매크로)를 뽑아 **이미지를 직접 보고 비평**한 뒤 고친다.
- 웹 빌드는 Playwright로 챕터 키프레임을 캡처해서 **Blender 레퍼런스 렌더와 나란히** 비교한다.

## 7. Blender 파이프라인

### 7.1 G0: 블렌더 방법론 심층 조사 (깊이 10/10, 브리프 필수 요구)

**원칙**: 이 조사를 끝내고 도하에게 보고해서 승인받기 전에는 블렌더 모델링, 렌더 작업을 시작하지 않는다(bpy 설치와 동작 확인까지만 한다).

> ✅ **완료 (2026-10-01)**: 보고서 [`research/blender-methodology.md`](research/blender-methodology.md), 규약 [`research/MBS.md`](research/MBS.md), 재현 스크립트 [`research/scripts/`](research/scripts/README.md). 도하 승인 대기.

**조사 범위**
1. **하드서피스 모델링 방법론 비교**: SubD + 서포트 루프 / 베벨 + 가중 노멀(게임 업계식) / 불리언 + 비파괴 스택(HardOps, BoxCutter 계열) / Mesh-to-SubD. 각각의 실제 사용처와 웹 실시간 적합성.
2. **유기적 형상 위의 하드서피스**: 조각된 근육 베이스에서 패널을 추출하는 워크플로우(패널 루프, 리토폴로지 후 분리, 쉬링크랩 + 솔리디파이), 필드 정렬 쿼드 리메싱(QuadriFlow, Instant Meshes).
3. **토폴로지와 스케일 표준**: 단위, 트랜스폼 적용, 법선, n-gon 정책, 폴리곤 예산.
4. **비파괴 워크플로우**: 모디파이어 스택 순서 규칙, 지오메트리 노드 절차적 디테일(체결부품 산포, 루버, 케이블/호스 라우팅).
5. **UV와 텍셀 밀도**: 일관된 텍셀 밀도, 트림 시트, 데칼, UDIM vs 아틀라스(웹 기준).
6. **베이킹**: 케이지, 레이 거리, 하이 → 로우, Cycles 베이크 설정, AO, 곡률, 두께, ID, glTF ORM 패킹.
7. **PBR 재질 표준**: 메탈/러프 워크플로우, 측정값 DB, 이방성, 블렌더 노드 → glTF 변환의 한계.
8. **색 관리**: AgX의 역사(Filmic → AgX), OCIO, 뷰 트랜스폼과 룩, 작업 색공간, 웹으로 가져가는 법.
9. **조명**: 제품 시각화 조명법, HDRI 제작, 실제 광량 단위.
10. **Cycles vs EEVEE**: 레퍼런스용과 베이크용 설정, 노이즈 제거(OIDN), 컨테이너 CPU 환경 최적화.
11. **glTF 익스포트 모범 사례**: 모디파이어 적용, 탄젠트, 커스텀 속성(extras), 애니메이션과 인스턴싱, 압축은 후처리로(gltf-transform).
12. **파이프라인 자동화**: bpy 헤드리스, CLI, 결정론적 빌드, .blend 버전 관리 전략, 명명 규칙, 컬렉션 계층.
13. **리깅**: 강체 부품의 본 페어런팅, 분수 회전 분배(라멜), 드라이버, IK, 기구학 제약.
14. **실시간용 최적화**: LOD, 디시메이션, 인스턴싱, 드로우콜.
15. **실사화 체크리스트**: 업계에서 널리 알려진 '렌더가 가짜처럼 보이는 이유' 계열의 원칙들(베벨, 스케일, 조명, 재질, 불완전함).
16. **업계 사례**: Blender Studio의 파이프라인 문서와 오픈 프로젝트, 하드서피스와 제품 시각화 전문가들의 공개 워크플로우, Polycount 위키(베이킹, 가중 노멀), Khronos glTF 문서, three.js 커뮤니티 모범 사례.

**방법**: 공식 문서와 1차 출처 우선. 주장마다 출처를 달고 신뢰도를 표기한다. 상충하는 관행은 비교표로 정리하고, 우리 프로젝트(웹 실시간, 헤드리스 자동화, 약 4,000개 부품)에 맞는 선택을 근거와 함께 제시한다.

## 8. 실시간 렌더링 (three.js)

### 8.1 렌더러 선택

- **1안(권장): `WebGPURenderer` + TSL(노드 셰이딩)**. WebGPU를 지원하지 않는 환경에서는 같은 코드가 **WebGL2 백엔드로 자동 폴백**한다. TRAA, GTAO, SSR, 모션 블러, DoF, 블룸, 3D LUT를 노드 기반 후처리로 구성할 수 있다.
- **2안(폴백): `WebGLRenderer` + pmndrs/postprocessing**.
- **결정 게이트**: P0 스파이크에서 Artifact 환경 안의 WebGPU 가용성, 성능, 기능을 확인하고 결정한다.

### 8.2 씬 구조

- **BatchedMesh**: 재질별로 하나씩(티타늄, TiN, 블랙 아노다이즈, 엘라스토머, 패브릭, 바이저, 발광). 수백 개 부품을 **단일 드로우콜**로 그리면서 부품마다 행렬을 매 프레임 갱신해 조립 애니메이션을 만든다. LOD는 인스턴스별 지오메트리 ID를 교체해서 처리한다.
- **InstancedMesh**: 체결부품 수천 개.
- **스트리밍**: 챕터 단위 glTF 청크. 히어로 에셋을 먼저 받고, 나머지는 프롤로그와 읽는 시간 동안 백그라운드로 받는다.
- **가시성 관리**: 챕터별로 필요한 서브시스템만 렌더(내부 기계는 04~06, X-ray, 10에서만).
- 목표 드로우콜: 50 이하(그림자 패스 제외).

### 8.4 조명과 환경

- Blender에서 만든 스튜디오 HDRI → **UltraHDR(게인맵 JPEG)** 로 경량화 → PMREM.
- 키/림 RectAreaLight 2~4개(스크롤에 연동해 이동), 그림자용 방향광 1개(PCSS 계열 소프트 섀도).
- 바닥: 반사 + 접지 AO.

### 8.5 후처리 체인 (순서)

`장면 렌더 (+ 속도 버퍼) → GTAO → SSR → 선택적 블룸 → 피사계 심도 → 모션 블러 → TRAA → 색수차 / 비네팅 → AgX 3D LUT (Blender 베이크) → 필름 그레인 → 출력 (sRGB)`

### 8.6 색 파이프라인 일치 (AgX)

1. Blender 5.2.1: 뷰 트랜스폼 **AgX**, 룩 None, 디스플레이 sRGB, 작업 색공간 Linear Rec.709, 노출 0.
   - G0 실측: three.js 내장 AgX vs Blender AgX = 컬러차트 평균 ΔE 3.91(최대 6.2), 시그널 오렌지/빨강 발광체 최대 ΔE 약 7 → LUT 필수. log2 셰이퍼 + 65³ LUT(trilinear) 재현 오차 평균 0.068 / 최대 0.832 (조사 보고서 §11).
2. **PyOpenColorIO(pip)** 로 Blender의 AgX 뷰 트랜스폼을 **셰이퍼 + 65³ 3D LUT** 로 베이크.
3. three.js: 톤매핑 OFF(Linear 출력) → 후처리 마지막에 **LUT 노드**로 Blender와 동일한 변환을 적용.
4. 대조군: three.js 내장 `AgXToneMapping`과 비교해서 차이를 기록.
5. **검증**: 동일한 컬러차트 + 그레이 램프 장면(무조명 발광면)으로 ΔE2000 평균 1.5 이하. 조명 금속 구체는 4 이하(패스트레이싱과 래스터의 차이를 감안).

## 9. 인터랙션과 손맛

### 9.1 커서

1. **점검 조명**: 커서 레이가 닿은 표면을 향하는 가상 조명. 하이라이트가 이방성 결을 따라 미끄러진다. 재질의 진짜 정체가 드러나는 순간.
2. **시선 추적**: 마스크가 커서를 따라 돈다(목 ROM 안에서, 감쇠 스프링). 목 라멜이 실제로 분수 회전으로 미끄러진다. 히어로에서 바로 목 설계를 증명한다.
3. **근접 긴장**: 커서 근처 패널이 0.5~1 mm 긴장하고 상태광이 밝아진다. 미세한 서보 틱.
4. **정밀 레티클 커서**: 크로스헤어 + 슈트 표면 좌표(mm) 표시. 부품에 **자석처럼 스냅**하고 리더선 콜아웃이 그려진다. 커서 자체에 미세한 질량(스프링 추종)이 있다.
5. **길게 누르기**: 근육 수축(키네틱 벌지), 루버 개방.
6. **드래그**: 오비트(관성 + 15° 간격 디텐트 클릭), 사지 조작(IK + 관절 제한).

### 9.2 스크롤

- **Lenis**(부드러운 가상 스크롤) + **GSAP ScrollTrigger**(챕터 타임라인). GSAP는 2025년부터 플러그인까지 전부 무료.
- **마스터 타임라인**: 스크롤 진행도 p → 모든 3D 상태 = 순수 함수 f(p). 누적 상태가 없으니 **역방향 스크롤 시 완전히 분해**된다.
- **이벤트 교차 감지**: 프레임 사이에 체결 임계값을 지나면 방향별 사운드(체결음 / 해제음)를 트리거.
- **스크롤 디텐트(실험)**: 체결 임계값 근처에서 스크롤 이득이 약 100 ms 동안 60%로 떨어진다. 기계식 휠의 '노치'처럼 느껴진다. A/B 테스트 후 강도를 정하고, reduced-motion에서는 끈다.
- **속도 반응**: 스크롤 속도 → 모션 블러 강도, 서보음 피치, 사운드 모드 전환(§10).
- **챕터 눈금자**: 화면 가장자리의 측정 눈금자 = 진행도. 클릭하면 점프(빨리감기 래칫음).

| 0~90 ms | **히트스톱** | 실시간 이펙트 레이어만 40~90 ms 정지(질량 등급별). 스크롤 위치는 건드리지 않음 | | |
| +60 ms | 확인 | 상태 LED 블립, (히어로 부품) 콜아웃 | 소프트 칩 | |
| +80 ms~ | 체결부품 | (히어로 부품) 스크류 회전 진입 | 토크 드라이버 와인 → 클러치 '틱' | 틱마다 미세 펄스 |
| ~600 ms | 꼬리 | | 모달 공명 감쇠 + 공간 반사 | |

**질량 등급**: S(20 g 미만) / M(20~150 g) / L(150~600 g) / XL(600 g 이상: 마스크, 배터리, 대흉근). 등급마다 임펄스, 히트스톱, 저역량, 진동 강도를 스케일한다.

### 9.4 의사 햅틱 (Pseudo-haptics)

시스템 커서를 숨기고 가상 커서를 그리면 **C/D 비율**(마우스 이동 대비 커서 이동)을 조작할 수 있다. 이것만으로 사람은 **무게, 마찰, 저항**을 느낀다(HCI에서 검증된 기법).

- **무거운 부품 드래그**: 커서가 마우스보다 느리게 따라온다 → 무겁다.
- **토크렌치**: 규정 토크에 다가갈수록 C/D가 떨어지며 저항이 커지다가, 규정값에서 '딸깍' + **커서가 앞으로 툭 튀어나감**(렌치 슬립) + 플래시 + 진동.
- **디텐트 노브와 페이더**: 디텐트 사이에서 커서가 홈으로 빨려 들어가는 자석 효과.
- **마스터 스위치(프롤로그)**: 누르는 깊이에 따라 저항이 커지다가 넘어가는 순간 해방.
- 드래그 인터랙션은 Pointer Lock을 우선 사용(Artifact iframe에서 막히면 가상 커서 방식으로 폴백).

### 9.5 실제 진동

> **P0 실측 (2026-10-02)**: iPhone(iOS 18.7, Claude 앱) switch 햅틱 ✅ 느껴짐 → 확정 채택. 기울기 센서는 아티팩트 iframe에서 권한 거부 → 기울기 조명 폐기, 모바일은 터치 드래그로 대체. 전체 화면은 데스크톱만. 포인터 잠금은 데스크톱 ✅.



- **Vibration API**(Android Chrome 계열): 질량 등급별 패턴. 예) S `[6]`, L `[10, 24, 14]`, XL `[18, 30, 26]`, 래칫 `[4, 14] × n`.
- **iOS(실험)**: iOS 18 이상 Safari의 `<input type="checkbox" switch>` 토글 시 시스템 햅틱이 발생하는 성질을 사용자 제스처 안에서 활용. Artifact iframe 안에서 되는지 스파이크로 확인.
- **게임패드(선택)**: `vibrationActuator`로 듀얼 럼블.
- 설정에서 진동을 켜고 끌 수 있다.

## 10. 사운드 디자인

### 10.0 도하 피드백 반영 (2026-10-02, P0 청음)

- **체결음 목표 = '철컥'**: 경화강 폴이 걸리는 밝은 '철' + 패널이 하드 스톱에 안착하는 단단한 '컥' + 미세 바운스. '뚱'(저역 위주)은 금지. 상세: [`reviews/P0-platform.md`](reviews/P0-platform.md) §6.
- **부품과 물성마다 다른 소리**: 체결음 파라미터는 부품 크기·두께·질량·접촉 재질에서 계산한다(같은 소리 재사용 금지, 변주는 시드).
- **나사 체결 = 로봇팔 너트러너**: 모터음, 유성기어 맞물림음, 토크 상승, 클러치 이중 클릭.
- **유압 부품 = 유압음**: 밸브 포핏 클릭, 펌프 맥동, 유량 히스, 안착음.
- 출력 지연이 큰 환경(블루투스, 약 170 ms 실측)에서는 화면의 충격 효과를 소리에 맞춰 늦춘다.

### 10.1 원칙

1. **소리도 물성에서 나온다.** 패널의 크기, 두께, 재질, 접촉 상태가 소리를 결정한다.
2. **반복은 기계처럼 들린다.** 모든 이벤트에 변주(피치 ±3%, 게인 ±1.5 dB, 레이어 조합 랜덤)를 준다.
3. **소리가 공간에 있다.** 부품이 체결되는 3D 위치에서 들린다(HRTF 패닝).
4. **음악보다 기계음이 주인공.** 스코어는 최소한으로.

### 10.2 엔진 구조

```
[이벤트 버스] → SoundEvents 매퍼 (부품 메타데이터 → 파라미터)
   ├─ ModalSynth (AudioWorklet): 패널 공명
   ├─ MotorSynth: BLDC 와인 (각속도 연동, 극쌍 × rpm 고조파 + 기어 메시 주파수)
   ├─ HydraulicSynth: 펌프 맥동, 유량 히스(속도 연동), 밸브 틱
   ├─ GranularRatchet: 고속 스크롤 시 체결음 스트림
   ├─ Sampler: 소량의 유기적 텍스처 샘플
   └─ Spatializer (PannerNode HRTF)
        ↓
 버스: Mechanical / UI / Ambience / Score  →  사이드체인 더킹  →  컨볼루션 리버브 (합성 IR: 소형 스튜디오, 행거)  →  리미터  →  출력
```

- 지연: AudioContext `latencyHint: 'interactive'`, 버퍼를 미리 디코드. 목표 이벤트 → 소리 20 ms 이하.
- 보이스 관리: 동시 발음 수 제한, 보이스 스틸링, 고속 연쇄 시 그레인 래칫으로 전환(원칙 L).

### 10.3 합성 기법

- **모달 합성**: 판의 고유진동수 근사 f ∝ (t / a²) · √(E / ρ(1−ν²)) × 형상/곡률 계수. 티타늄 E = 113.8 GPa, ρ = 4,430 kg/m³, ν = 0.34. 히어로 부품은 **FEM 고유치 해석**(선택)으로 실제 모드를 뽑는다. 아이솔레이터 위 패널은 감쇠가 크게(T60 0.05~0.2 s), 금속끼리 닿는 부품은 길게.
- **여기(excitation) 모델**: 접촉 경도(Ti-Ti, Ti-엘라스토머, Ti-폴리머 가이드)에 따라 여기 스펙트럼을 바꾼다.
- **모터**: 실제 시뮬레이션 각속도로 구동되는 실시간 합성 → 슈트가 움직이는 만큼 정확히 소리가 난다.
- **유압**: 펌프 맥동(피스톤/기어 수 × rpm) + 필터링된 노이즈 히스(유량 비례) + 릴리프.

### 10.4 사운드 카탈로그 (약 120종, 변주 포함 약 400+)

| 분류 | 내용 |
|---|---|
| 체결 | 질량 4등급 × 접촉 3종 × 변주 6 + 해제음 |

| 구동 | BLDC 와인, 파동기어 험, 케이블 텐션, 풀리 틱, 실린더 슬라이드/히스, 솔레노이드, 펌프 스풀업/정상/맥동, 축압기 충전, 릴리프 |

### 10.5 믹스 기준

- 통합 음량 **−18~−16 LUFS**, 트루 피크 **−1 dBTP 이하**.
- UI는 체결음보다 약 6 dB 작게. 히어로 이벤트 때 앰비언스 3 dB 더킹.
- 마스터 볼륨과 버스별 볼륨(설정 패널).

### 10.6 검증 (정직하게: 나는 소리를 직접 들을 수 없다)

- OfflineAudioContext로 헤드리스 렌더 → WAV → **스펙트로그램 이미지를 직접 보고** 어택, 감쇠, 대역, 음량(LUFS), 크레스트 팩터를 분석한다.
- 실제 기계음의 특성(금속 클릭 어택 2 ms 미만, 마운트된 패널 T60 등)과 대조한다.
- **최종 판단은 도하의 귀**: G3(버티컬 슬라이스)와 G6(사운드 베타)에서 청음 체크리스트로 피드백을 받는다.

| 1회 발행 255개 파일, 64 MB / 버전당 511개, 256 MB | 총 60 MB 이하 목표. 넘으면 같은 URL에 여러 번 나눠 발행 |
| 외부 스크립트 CDN 제한 | Vite가 전부 번들 → 외부 의존 없음 |
| 표준 웹 미디어 타입만 | wasm(basis 트랜스코더)의 MIME 허용 여부 스파이크 확인. 안 되면 meshopt(JS 내장) + WebP 텍스처로 폴백 |
| iframe 샌드박스 가능성 | WebGPU, AudioContext, Pointer Lock, Vibration, DeviceOrientation 가용성을 **P0 스파이크에서 실측** |
| 기본 비공개 | 공개 범위는 도하가 결정 |

## 16. 도하에게 확인받을 결정

G1까지 정하면 되지만, 일찍 알려주면 계획이 더 정확해진다.

1. ~~**마스크**: 드로잉의 헬멧 디테일을 그대로 갈지, 오리지널 'PERSONA'로 갈지~~ → ✅ **확정 (2026-10-01): PERSONA**. 드로잉의 실루엣과 비율은 유지하고, 디테일은 안면근 해부도 기반 오리지널(§5.7)
2. **기본 마감**: 비드블라스트 티타늄 기본 + TiN 골드 포인트(관절 링, 체결부품, 툴 베이 테두리) vs 전신 골드. → 추천: 티타늄 기본 + 골드 포인트, 피날레에서 전신 골드로 전환 가능
3. **도하의 원본 드로잉을 SCHEMA 챕터에 크레딧과 함께 넣어도 되는지.**
4. **사이트 언어**: 영문 엔지니어링 라벨 + 한글 본문(KO/EN 전환) → 추천
5. **크레딧 표기 방식** (이름 표기, 연락처나 링크 포함 여부)
6. **상태광 색 체계**(§5.6 가안). 특히 '구동 중' 색(시안 vs 대안)
7. **음악**: 기계음만 vs 미니멀 생성형 스코어 추가
