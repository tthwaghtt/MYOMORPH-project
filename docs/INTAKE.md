## 0. 원칙 (PLAN §2.2)

1. **레퍼런스 = 설계도.** 검정 굵은 선 = 판 틈, 파랑 가는 선 = 판 안의 꺾임, 빨강 점선 = 가려진 선과 겹침, 초록 = 나사·통풍구·조명·디스크.
2. **판은 독립 솔리드.** 한 장의 껍데기에 홈을 내지 않는다.
3. **해석하지 않는다.** 근육 모티프나 내 취향을 더하지 않는다. 모르는 곳은 묻고, 임시로 채운 곳은 `provisional`로 표시한다.
4. **비율 조정은 작게, 보고한다.** 5 %를 넘으면 먼저 묻는다.
5. **도하 몸 모델은 확인용.** 여유, 장치 깊이, 가동 범위를 검사할 때만 쓴다.
6. **도하의 원본은 고치지 않는다.** `incoming/`의 파일은 읽기만 하고, 모든 중간 결과는 `reference/work/`에 따로 쓴다.
7. **단계마다 보고하고 동의를 받는다.** 특히 1단계 뒤, 4단계 시험 부위 뒤, 6단계 충돌 목록 뒤.

## 1. 받기와 검토

**입력**: `incoming/`의 파일, 또는 대화에 첨부된 이미지(받으면 바로 `incoming/`에 저장하고 커밋한다).

**할 일**
1. 파일마다 형식(SVG 레이어 / 레이어별 PNG / 한 장짜리 래스터), 축척(템플릿 사용 여부, 축척 막대), 레이어 이름과 색을 확인한다.
2. GUIDE §4의 뷰 목록과 맞춰 본다.
   - 필수: 정면, 후면, 측면(팔 없이), 팔 4면, 다리 안쪽, 헬멧 4면 + 얼굴
   - 권장: 윗면, 손·부츠, 단면, 굽힌 자세, 상세도, 분위기 그림
3. 선 품질을 본다: 판 윤곽이 닫혔는지, 해칭이 있는지, 같은 선을 여러 번 그었는지, 색과 레이어가 섞였는지.
4. 비대칭 표시(오른 전완 툴 베이, 왼 전완 교체 포트 등)와 도하의 메모(레이어 15)를 모두 읽는다.

**출력**: `work/inventory.md`
- 파일 표(이름, 뷰, 형식, 축척, 품질, 문제)
- 빠진 뷰와 그 영향
- **질문 목록**(Q1, Q2, …): 뜻이 헷갈리는 선, 빠진 면, 겹침 방향, 대칭 여부, 재질 표시, 여닫는 방식

**보고**: 목록, 질문, 다음 단계 계획 → **도하의 동의를 받고** 2단계로 간다.

## 2. 뷰별 벡터화

**할 일**
- **SVG**: 레이어를 읽는다. Inkscape는 `inkscape:groupmode="layer"`와 `inkscape:label`, Illustrator는 그룹 `id`가 레이어 이름이다. 변환 행렬을 풀고, 경로를 0.5 mm 이하 간격의 폴리라인으로 바꾼다. 선 종류는 레이어 이름 우선, 없으면 색으로 나눈다.
- **레이어별 PNG**: 색으로 분리 → 세선화 → 선 추적 → 단순화(0.3 mm) → 끝점 붙이기(1.5 mm 이내) → 닫힌 윤곽 만들기.
- **한 장짜리 래스터**: 색 분할을 시도하되, 색으로 뜻이 구분되지 않으면 **추측하지 않고** 도하에게 묻는다.
- 판 ID(레이어 14)와 메모(레이어 15)의 글자 위치를 기록한다.

**출력**: 뷰마다 `work/<view>.json`

```jsonc
{
  "view": "front", "source": "incoming/MK1_ref_v1_front.svg",
  "mm_per_unit": 1.0, "template": true,
  "lines": [ { "class": "edge|crease|hidden|feature", "closed": true, "pts": [[x, y], ...] } ],
  "ids":   [ { "text": "T-03", "pos": [x, y] } ],
  "notes": [ { "text": "굽히면 위로 미끄러짐", "pos": [x, y] } ]
}
```

그리고 확인 이미지 `work/<view>_check.png`(선 종류별 색, 닫힌 영역 번호, 끊긴 끝점 표시). **내가 직접 이미지를 보고** 원본과 비교한다.

**확인**: 닫힌 영역 수, 끊긴 끝점 0개(남으면 목록), 선 종류 비율.

## 3. 뷰 정합 (뷰끼리, 그리고 몸과)

**할 일**
1. 템플릿 위에 그렸으면 SVG 좌표가 곧 mm다(정면 x = 좌우, 측면 x = 앞뒤, y = 아래쪽 + 높이). 템플릿 없이 그렸으면 높이선과 축척 막대로 뷰마다 축척과 위치를 맞춘다(회전은 꼭 필요할 때만).
2. 같은 판이 여러 뷰에 보이면 위끝과 아래끝 높이가 같은지 잰다. 정면과 후면의 폭, 측면과 윗면·단면의 깊이도 맞춰 본다.
3. 레퍼런스 바깥선을 템플릿 몸과 판 바깥면 최소선(피부 + 12 mm)에 겹친다. 최소선 안으로 들어온 곳은 **몸과 부딪히는 곳**으로 표시한다.

**출력**: `work/registration.json`(뷰별 변환, 잔차 mm), `work/mismatch.md`(뷰끼리 어긋난 곳, 몸과 부딪히는 곳, 질문)

**확인**: 높이 잔차 중앙값 2 mm 이하. 넘는 곳은 정면·측면을 기준으로 삼고 질문 목록에 넣는다.

## 4. 판 목록과 판 솔리드

### 4a. 판 목록
- 검정 닫힌 영역 하나 = 그 뷰에서 보이는 판의 한 면.
- 판 ID가 있으면 ID로, 없으면 높이 띠, 좌우 위치, 이웃 관계로 뷰 사이의 같은 판을 짝짓는다.
- 판마다 기록: ID, 보이는 뷰, 이웃 판, 겹침 순서(빨강 점선 = 아래 판), 안쪽 꺾임선, 피처(나사, 통풍구, 조명, 디스크), 좌우 대칭, 역할 태그(D/P/F/M/S/V/L, PLAN §5.3).
- 역할 태그와 장치 배정(어느 판이 배터리, 루버, 툴 베이인지)은 **제안**으로 표시하고 도하에게 확인받는다.
- 출력: `work/panels_catalogue.json`, 판 번호가 적힌 뷰별 확인 이미지.

### 4b. 바깥 곡면
레퍼런스 자체의 형상에서 만든다. **마네킹 피부를 부풀린 면을 쓰지 않는다.**
1. **레퍼런스 외곽 몸체**: 정면·측면·후면 실루엣(높이별 폭과 깊이)과 윗면·단면(높이별 단면 모양)으로 몸통, 팔, 다리, 헬멧의 외곽을 만든다. 단면이 없는 높이는 가까운 단면 사이를 보간하고, 단면이 하나도 없으면 높이별 폭과 깊이로 만든 둥근 사각 단면을 쓰고 `provisional`로 표시한다.
2. **판 경계를 3D로**: 판이 가장 정면으로 보이는 뷰에서 그 판의 검정 윤곽을 외곽 몸체에 그 뷰 방향으로 투영한다. 두 뷰에 걸친 판(예: 앞과 옆을 감싸는 판)은 실루엣 선에서 이어 붙인다.
3. **꺾임을 진짜 모서리로**: 두 뷰에 보이는 파랑 선은 높이를 맞춰 3D 곡선으로 바로 계산하고(정면 x(z) + 측면 y(z)), 면이 그 곡선을 지나 꺾이도록 판 곡면을 고친다. 꺾임 사이는 레퍼런스가 평평해 보이면 평면, 둥글어 보이면 낮은 차수 곡면으로 채운다.
4. **판의 높이차**: 측면 실루엣이나 단면에서 판 가장자리가 계단처럼 보이면 그만큼 판을 바깥으로 띄운다. 겹치는 곳은 빨강 점선의 순서대로 위 판을 판 두께 + 틈만큼 바깥에 둔다.

### 4c. 솔리드와 디테일 (PLAN §5.3 공학 규칙)
- 판 두께 0.6 mm(잠정) + 안쪽 헴 2~4 mm. 레퍼런스의 판 모서리가 두꺼워 보이면 헴과 플랜지로 그 두께를 낸다.
- 0.4 mm 챔퍼, 틈은 경계에서 양쪽으로 0.75 mm씩 깎아 1.5 mm(슬라이딩 판 2.5 mm). 손그림 선 굵기는 쓰지 않는다.
- 체결점은 판 크기에 따라 2~4곳, 초록 피처(나사, 통풍구 슬랫, 라이트파이프, 디스크)는 그 자리에 실제 부품으로 만든다.
- 판 ID, 역할 태그, 재질(`previs/materials.py` 키), 체결점을 객체 속성으로 붙인다.

### 4d. 시험 부위 먼저
**한 부위(가슴 판 묶음 또는 오른 전완)를 먼저** 끝까지 만들고, 레퍼런스와 같은 정사영으로 렌더해 원본 위에 겹친 이미지와 3/4 렌더를 도하에게 보여 준다. 방법을 승인받은 뒤 전체로 넓힌다.

**출력**: `myoforge/out/panels.blend`(무시), `work/panels_check_<view>.png`(겹침 이미지), `engineering/panels.json`(7단계에서 확정)

**확인**: 판 경계와 레퍼런스 검정 선 사이 거리가 중앙값 2 mm 이하, 최대 5 mm 이하. 판 수와 이웃 관계가 판 목록과 100 % 같다.

## 5. 비율 조정 보고

판은 4단계에서 **레퍼런스 좌표 그대로** 만든다. 이 단계에서 도하의 몸에 맞게 옮긴다.

1. 구간별 길이와 폭을 비교한다: 머리, 목, 몸통, 골반, 허벅지, 정강이, 발, 위팔, 전완, 손.
2. 몸통과 다리는 높이 방향으로, 팔은 팔 축 방향으로, 구간 경계에서 부드럽게 이어지는 구간별 선형 변형을 쓴다. 판 하나 안의 모양 비율은 그 구간의 배율 말고는 바꾸지 않는다.
3. 규칙: 2 % 이하는 그냥 적용(목록에는 적음), 2~5 %는 적용하고 보고, **5 % 초과는 적용 전에 도하에게 묻는다.**
4. 템플릿 위에 그렸다면 조정은 거의 없어야 한다. 그래도 몸과 부딪히는 곳(3단계)이 있으면 판을 옮기는 대신 그 판만 바깥으로 띄우는 안과 함께 보고한다.

**출력**: `work/proportion_report.md`(구간 | 레퍼런스 mm | 도하 mm | 배율 % | 비고)와 전후 겹침 이미지.

## 6. 공간·가동 범위 검사

1. **여유**: 판 바깥면이 피부 + 12 mm 바깥에 있는지 판마다 잰다.
2. **장치 깊이**: 장치를 몸 랜드마크에 놓고, 장치 발자국 안 하위 10 % 거리를 가용 깊이로 본다. PLAN §5.13의 필요 깊이(장치 두께 + 8.6 mm)와 비교한다.
3. **가동 범위**: 판을 가장 가까운 몸 분절에 붙이고 포즈 약 40개로 돌린다. 무릎 0~125°, 팔꿈치 0~135°, 어깨 굽힘 160° · 벌림 150°, 고관절 굽힘 110°, 목 회전 ±70° · 숙임 40°, 허리 숙임 60°, 스쿼트. 판끼리, 판과 몸의 침투를 잰다(설계한 겹침은 제외).
4. **브리프 규칙**: 관절을 가로지르는 강체판, 통짜 흉갑, 갈비뼈 모양 루버, 위로 열리는 루버를 자동으로 찾는다. 레퍼런스와 부딪히면 도하에게 묻는다.

**대응 순서**(충돌마다): 내부 배치 변경 → 장치 재설계(더 얇게) → 성능 조정 → 외형 변경은 도하에게 문의.

**출력**: `work/space_report.md`(충돌 목록, 깊이 지도 이미지, 대응 제안) → **도하에게 보고하고 동의를 받는다.**

검사기는 새로 만든다(MYOFORGE B16). 이전의 `clearance.py`, `modules.py`는 폐기한 셸 전용이었다.

## 7. 수치 다시 계산

1. `engineering/panels.json`을 쓴다. 스키마는 `provisional_inputs.json`과 같은 키에 판별 목록을 더한다.

   ```jsonc
   {
     "status": "reference MK1_ref_v1 (날짜)",
     "shell_area_m2": 0.0,
     "panel_groups": [ { "name": "torso + limbs front", "n": 0, "size": 1.0, "mounts": 3 } ],
     "panels": [ { "id": "MM1-MYO-CH-T03-L-01", "ref_id": "T-03", "group": "...", "area_m2": 0.0, "mounts": 3, "roles": ["D"], "side": "L" } ]
   }
   ```
2. `engineering/calc.py`가 `panels.json`을 읽게 바꾸고(`PI = J('engineering', 'panels.json')`), `provisional_inputs.json`을 지운다. `report.py`의 잠정 경고(PROV)를 레퍼런스 출처 한 줄로 바꾼다.
3. 판 목록에 따라 함께 정할 값:
   - **배터리 등판**: 1장에 셀 14개(70 × 55 mm)가 들어가려면 판 면적이 0.067 m² 이상(충전율 80 %)이고 장치 두께 9 mm가 필요하다. 모자라면 판 두 장을 한 팩으로 묶거나, 셀 수를 줄이고 가동 시간을 다시 보고한다.
   - 로봇 판 픽 수(지금 168, 판 세트 단위), 라이트파이프 수(지금 124, 이음선 길이에 비례), 체결점 수.
4. `python3 engineering/calc.py && python3 engineering/report.py`를 돌리고 바뀐 숫자를 전후 표로 만든다.
5. 숫자를 옮긴다: PLAN §0, §5.2, §5.4, §5.9, §5.14(`design/_plan_tables.md`의 표를 붙여 넣는다), COPY와 STORYBOARD의 카운터, 계획 웹페이지. "잠정" 표시를 지운다.

**출력**: 바뀐 수치 표(전 → 후)가 들어간 커밋.

## 9. 스토리보드와 페이지 갱신

- STORYBOARD, COPY, BIBLES의 ⏳ 표시를 레퍼런스 내용으로 바꾼다(판 수, 판 이름과 순서, 헬멧 연출, 따로 움직이는 판, 골드 포인트 위치).
- 계획 웹페이지를 갱신한다.
- 스토리보드 아티팩트는 **조금씩** 고친다. 한 번에 완성하려 하지 않는다(도하 지시).

## 11. 도하에게 물어볼 질문 틀 (1단계에서 실제 목록으로 만든다)

- 이 두 판은 어느 쪽이 위로 겹치나요? 굽힐 때 어느 판이 밀려 들어가나요?
- 좌우가 같은가요? 다른 곳은 어디인가요?
